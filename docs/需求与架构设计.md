> 版本：v1.0（草案）
> 日期：2026-09-21

## 0. 一句话概览

用 **STM32F103C8T6** 做运动控制板，用**一条串口总线**驱动 **7 个 ZDT Y42 闭环步进电机**（4 个麦轮底盘 + 3 个三轴臂关节）+ 1 个舵机夹爪；**树莓派**跑 ROS2 做感知与决策，通过**自定义串口协议**把速度/位姿指令下发、把里程计回传。

---

## 1. 需求理解

### 1.1 系统角色划分

| 层级 | 硬件 | 职责 | 实时性要求 |
|---|---|---|---|
| 决策/感知层 | 树莓派（ROS2 Humble/Jazzy） | 激光雷达 SLAM、Maxicam 视觉识别、路径规划、任务调度 | 10–30 Hz，容忍抖动 |
| 运动控制层 | STM32F103C8T6 | 麦轮逆运动学、三轴臂插补、7 电机总线调度、舵机 PWM、安全逻辑 | 50–100 Hz 硬周期 |
| 执行层 | 7× ZDT Y42 + 1× 舵机 | 速度/位置闭环执行 | 电机内部 20 kHz 闭环 |

**分工原则**：STM32 不做任何决策，只做「把上层指令变成确定性的电机帧」；树莓派不做任何硬实时控制。两者用一条 UART 解耦。

### 1.2 执行器清单

| 编号 | 地址 | 所属 | 功能 | 控制模式 | 建议心跳 |
|---|---|---|---|---|---|
| M1 | `0x02` | 底盘 | 麦轮 左前 (FL) | Emm 速度模式 | 200 ms |
| M2 | `0x03` | 底盘 | 麦轮 右前 (FR) | Emm 速度模式 | 200 ms |
| M3 | `0x04` | 底盘 | 麦轮 左后 (RL) | Emm 速度模式 | 200 ms |
| M4 | `0x05` | 底盘 | 麦轮 右后 (RR) | Emm 速度模式 | 200 ms |
| M5 | `0x06` | 三轴臂 | Yaw 旋转轴 | Emm 位置模式 | 500 ms |
| M6 | `0x07` | 三轴臂 | 上下升降轴 | Emm 位置模式 | 500 ms |
| M7 | `0x08` | 三轴臂 | 左右伸缩轴 | Emm 位置模式 | 500 ms |
| S1 | — | 三轴臂 | 夹爪开合舵机 | 50 Hz PWM | — |

> **地址分配刻意跳过 `0x01`**。原因见 §3.2 —— 地址 1 的电机有一条特殊的「自动应答」行为，把它空出来还能兼作单机调试地址。
> 广播地址 `0x00` 保留给多电机命令和同步触发。

### 1.3 已确定的技术选型（本次确认）

- ✅ **固件类型：Emm 固件**（绿灯常亮）。因此**没有力矩模式**，夹爪改用舵机是正确选择。
- ✅ **通讯方式：UART，只接 TX**，不使用电机反馈。
- ✅ **夹爪：舵机**驱动。
- ✅ **STM32 ↔ 树莓派：自定义串口协议**（C8T6 只有 64 KB Flash / 20 KB RAM，micro-ROS 塞不进去）。

## 2. 关键结论：关于「一个串口控 7 个电机」到底好不好

**结论：方案可行，而且是正确的选择 —— 但成立的前提是必须先改一个电机参数，否则会踩坑。**

### 2.1 为什么可行

1. **协议天生支持多机总线**。Y42 的串口帧格式是 `地址 + 功能码 + 数据 + 校验`，地址域 1–255，`0` 为广播。这本来就是一条总线挂多机的设计。
2. **有「多电机命令」这个杀手锏**（功能码 `0xAA`）。一次发送就能把**多个电机的不同命令打包成一帧**，4 个底盘轮只需 **37 字节**、3 个臂关节只需 **44 字节**。这比「一个电机一个串口」的总开销还低。
3. **只发不收，彻底消除了总线争用**。串口多机挂载最难处理的就是「多个从机同时应答导致总线打架」。你不接 RX，这个问题根本不存在。

### 2.2 ⚠️ 必须做的前提：把「控制命令应答方式」改成 None

这是整份文档里**最重要的一条**。手册 5.8.6 明确写了：

> **控制命令应答方式**：`00–04` 分别表示 `None / Receive / Reached / Both / Other`
> - `None`：发送控制命令给电机，**电机只执行，而不会返回任何命令**；
> - `Receive`：只返回确认收到命令（**默认值**）。

**出厂默认是 `Receive`**，也就是每个电机收到命令后都会往总线上吐一帧 `地址 + 功能码 + 02 + 6B`。7 个电机挂在同一条线上，如果它们的 TX 引脚在物理上连在一起（TTL 多机接线图就是这么接的），**多个推挽输出同时驱动同一根线 = 总线打架，严重时可能损坏 IO**。

所以**七个电机在上机前，必须逐个用 USB-TTL + 官方上位机把这一项改成 `None`**。

> 💡 好消息：改成 `None` **只屏蔽控制命令的应答，不影响读取命令**。手册在多电机命令的注意事项里说「含有读取参数命令的，要避开地址 1 返回的确认收到命令（方法：可设置 Response 菜单为 None/Reached）」，反证了 `None` 模式下读取命令依然正常返回数据。这给你后面加里程计留了口子（见 §3.5）。

### 2.3 也不推荐 TTL 版做长线多机

RS485 版是差分总线，天然支持多机挂载、抗 PWM 干扰强，是机器人上的正解。不过既然你**只接 TX、且电机永不回话**，TTL 多机方案的风险已经被 §2.2 基本消解了 —— 没有从机输出，就不存在争用。所以：

- 如果你手上是 **RS485 版** → 用 RS485，最稳。
- 如果你手上是 **TTL 版** → 可以做，但务必：
  - 电机侧 TX 引脚**一律悬空不接**（不要让 7 个 TX 连到一起）；
  - 总线走线尽量短，远离电机相线和 PWM 线，必要时加 100 Ω 串阻 + 对地小电容滤毛刺；
  - `应答方式 = None` 这一步**不能省**。

### 2.4 带宽预算

Emm 固件单条命令长度：速度模式 **8 字节**，位置模式 **13 字节**。

| 场景 | 帧长 | @115200 | @500000 | @921600 |
|---|---|---|---|---|
| 底盘 4 轮打包（多电机命令） | 37 B | 3.21 ms | 0.74 ms | 0.40 ms |
| 三轴臂 3 关节打包 | 44 B | 3.82 ms | 0.88 ms | 0.48 ms |
| 底盘 @100 Hz + 臂 @20 Hz | — | **约 40% 占用** | 约 9% | 约 5% |

**建议把电机总线波特率提到 500000（配置码 `07`）或 921600（配置码 `08`）**。默认的 115200 虽然勉强够用，但一旦你后面加上里程计轮询（§3.5），40% 会迅速变成 80%。留余量。

> ⚠️ 改波特率需要通过命令下发（`5.6.x 修改驱动配置参数`），**先用 115200 逐个改完，再统一切换 STM32 侧波特率**，否则会失联。改完记得用上位机逐个验证。

## 3. TX-only 无反馈设计：收益、代价与对策

你选择「只用 TX、不要反馈」，这个决定在**底盘**上完全站得住，在**三轴臂**上要打一个问号。逐条说明。

### 3.1 为什么底盘用纯开环是可以接受的

Y42 是**闭环步进**，闭环在电机内部完成（力矩环/速度环/位置环都是 20 kHz）。也就是说：**只要命令送达，电机就不会丢步**。你不需要外部反馈来保证「轮子转到了指定速度」—— 这一点和普通开环步进电机有本质区别，也是这个方案的最大底气。

### 3.2 代价清单（必须知情）

| # | 失去的能力 | 实际后果 |
|---|---|---|
| 1 | 读不到「位置到达标志」`Prf_TF` | 机械臂**无法知道动作何时完成**，只能用「发命令 + 估算时间延时」 |
| 2 | 读不到堵转/过热/过流标志 | 机械臂卡死、夹取异常时**系统完全无感知**，可能持续堵转烧电机 |
| 3 | 读不到回零状态 | 上电回零是否成功**不可知**，失败后所有绝对位置全错 |
| 4 | 读不到实时位置 | **无法做里程计**（见 §3.4，这是最大的隐患） |
| 5 | 收不到回零完成/到位主动返回 | 无法用事件驱动，只能轮询式定时 |
| 6 | 命令帧被干扰丢失 | 电机静默不动，**上层完全不知道** |
| 7 | 串口线断了 | 同上，且底盘会「带着上一个速度指令一直冲」 |

### 3.3 对策（这些必须落实到代码里）

1. **心跳保护 —— 无反馈设计里最有价值的一道保险**
   配置命令 `0x68`：`Addr 68 38 <是否存储> <00> <时间4字节> Chk`。
   默认值 0（关闭）。建议底盘设 **200 ms**、臂设 **500 ms**。
   效果：设定时间内没收到任何正确命令，电机**自动急停**。这直接覆盖了上表第 6、7 条——串口断了或 STM32 挂了，车不会失控狂奔。

2. **周期性重发目标位置 = 抗丢包 + 维持心跳（一石二鸟）**
   STM32 侧为每个电机维护「当前目标」，以固定周期重发：
   - 底盘：速度命令天然就是 100 Hz 重发；
   - 三轴臂：用**绝对位置模式**（运动模式 `01`），每 100 ms 重发一次同样的绝对目标。
   Emm 固件支持**位置命令打断**（手册 5.1.3：新位置命令会实时更新、平滑过渡），所以重发不会造成抖动；而如果某帧丢了，下一帧自动补上。这比「发一次等结果」健壮得多。

3. **回零用硬件兜底，不依赖读数**
   - Yaw 轴 → **单圈就近回零（模式 `00`）**。靠磁编码器绝对角度，**完全不需要限位开关**，上电即知零位。
   - 升降/伸缩轴 → **限位回零（模式 `03`）** 或 **无限位碰撞回零（模式 `02`）**。碰撞回零把堵转位置当零点，也不需要开关，但会对机械结构产生冲击，长期有磨损；有空间就装限位开关更干净。

4. **上电自检流程固定化**
   上电后：使能所有电机 → 触发回零 → 延时等待 → 清零位置 → 进入就绪。全程靠**固定时序**而非读数。⚠️ 这个时序需要实测标定，写死在配置里。

5. **⚠️ 强烈建议：把 RX 那根线接上（就一根线，成本 ≈ 0）**
   即使 v1 代码完全不解析它。理由见下节。

### 3.4 ⚠️ 最大的隐患：没有里程计 = ROS2 导航做不起来

你后面要装**激光雷达**、要跑 **ROS2 决策**。ROS2 的导航栈（`nav2` / `slam_toolbox`）本质上需要 `/odom` 话题和 `odom → base_link` 的 TF 变换。**里程计从哪来？**

- ❌ 轮式里程计：需要实时轮速/位置 —— 你现在的 TX-only 设计读不到。
- ⚠️ 纯激光 ICP / 扫描匹配：能跑，但对快速旋转、长走廊、动态遮挡非常脆弱，比赛现场翻车率高。
- ⚠️ 纯 IMU：几秒内就漂到天上去了。

**这是目前方案里唯一一个「将来大概率要返工」的点。** 建议二选一：

- **方案 A（推荐，成本极低）**：接上 RX 线，STM32 用 `0x36`（读取实时位置）**轮询 4 个底盘电机**，算出里程计。
  代价：4 × (3 B 命令 + 8 B 返回) = 44 B 往返。@500000 波特率下约 0.9 ms，**完全可以接受**。轮询 20–50 Hz 就够 ROS2 用。
  注意：`应答方式=None` 只屏蔽控制命令应答，**读取命令照常返回**，所以这个方案和你的 TX-only 设定并不冲突。
- **方案 B**：先按纯 TX-only 做 v1，把 RX 焊盘/排针**预留出来**，库的传输层预留 RX 接口（见 §4.2），等需要时再启用。

无论选哪个，**硬件上先把 RX 那根线接上/留出排针**。事后补线比事前留线贵得多。

### 3.5 库的应对：传输层抽象

因为存在「现在不用反馈、将来可能要用」的分裂，`ZdtMotor.c/.h` 的**传输层必须做抽象**：

```c
typedef struct {
    void    (*tx)(const uint8_t *buf, uint16_t len);
    uint8_t (*is_tx_idle)(void);
    /* 以下在 TX-only 配置下置 NULL，库内部跳过所有解析逻辑 */
    uint16_t (*rx_pop)(uint8_t *buf, uint16_t max_len);
    void    (*on_frame)(const uint8_t *frame, uint16_t len);
} ZdtPort_t;
```

上层业务代码（底盘运动学、机械臂插补）**完全不需要知道有没有反馈**。将来从 TX-only 切到带反馈，只换 `ZdtPort_t` 的实现，业务代码一行不动。

## 4. 通用电机库 `ZdtMotor.c/.h` 设计规格

### 4.1 设计目标

| 目标 | 说明 |
|---|---|
| **通用** | 一个库同时支持 X 固件和 Emm 固件；一份代码支持任意数量电机、任意 UART |
| **总线视角** | 库的主体是「一条总线」，不是一个电机。7 个电机共享一条 UART |
| **零阻塞** | 禁止 `HAL_Delay`。所有命令先构帧入队，由 1 ms 定时器/DMA 发送完成中断驱动出队 |
| **可测** | 构帧函数是**纯函数**（输入参数 → 输出字节数组），可以脱离硬件在 PC 上单元测试 |
| **可扩展** | 传输层抽象，未来可接 CAN / RS485；固件类型可字段切换 |

### 4.2 分层架构

```
┌─────────────────────────────────────────────┐
│ 应用层  chassis.c / arm.c / gripper.c        │  麦轮运动学、插补、舵机
├─────────────────────────────────────────────┤
│ 调度层  ZdtBus_t                             │  总线、发送队列、帧间间隔、多电机打包、同步组
├─────────────────────────────────────────────┤
│ 构帧层  Zdt_BuildXxx()   ← 纯函数，可单测    │  每个协议命令一个构造函数
├─────────────────────────────────────────────┤
│ 传输层  ZdtPort_t        ← 函数指针抽象      │  UART TX(DMA) / 预留 RX 解析
└─────────────────────────────────────────────┘
```

### 4.3 核心数据结构

```c
/* ---------- 枚举 ---------- */
typedef enum { ZDT_FW_EMM = 0, ZDT_FW_X = 1 } ZdtFirmware_t;

typedef enum { ZDT_DIR_CW = 0x00, ZDT_DIR_CCW = 0x01 } ZdtDir_t;

/* 运动模式：位置模式第三个参数字段 */
typedef enum {
    ZDT_POS_REL_LAST = 0x00,  /* 相对「上一输入目标位置」相对运动 */
    ZDT_POS_ABS_ZERO = 0x01,  /* 相对「坐标零点」绝对运动  ← 机械臂推荐 */
    ZDT_POS_REL_NOW  = 0x02   /* 相对「当前实时位置」相对运动 */
} ZdtPosMode_t;

typedef enum {
    ZDT_HOME_NEAREST   = 0x00,  /* 单圈就近回零      ← Yaw 轴推荐 */
    ZDT_HOME_DIRECTION = 0x01,  /* 单圈方向回零 */
    ZDT_HOME_COLLIDE   = 0x02,  /* 无限位碰撞回零    ← 无开关时的选择 */
    ZDT_HOME_LIMIT     = 0x03,  /* 限位回零          ← 有开关时推荐 */
    ZDT_HOME_ABS_ZERO  = 0x04,  /* 回到绝对位置坐标零点 */
    ZDT_HOME_POWERLOSS = 0x05   /* 回到上次掉电位置 */
} ZdtHomeMode_t;

/* 同步标志：00 立即执行 / 01 先缓存，等广播触发 */
typedef enum { ZDT_EXEC_NOW = 0x00, ZDT_EXEC_SYNC = 0x01 } ZdtSync_t;

/* ---------- 电机句柄 ---------- */
typedef struct {
    uint8_t       addr;         /* 1–255；0 为广播 */
    ZdtFirmware_t fw;           /* Emm / X */
    uint16_t      microstep;    /* 细分，默认 16 */
    float         gear_ratio;   /* 输出轴 : 电机轴，默认 1.0 */
    float         max_rpm;      /* 软件限幅，默认 3000 */
} ZdtMotor_t;

/* ---------- 总线句柄 ---------- */
#define ZDT_TXQ_DEPTH   8
#define ZDT_MOTOR_MAX   16

typedef struct {
    ZdtPort_t   *port;
    ZdtMotor_t  *motors;
    uint8_t      motor_cnt;
    uint8_t      csum_mode;     /* 0=固定 0x6B  1=XOR  2=CRC8  3=Modbus */
    /* 发送队列 */
    uint8_t      txq[ZDT_TXQ_DEPTH][ZDT_FRAME_MAX];
    uint16_t     txq_len[ZDT_TXQ_DEPTH];
    uint8_t      head, tail;
    uint32_t     last_tx_tick;  /* 用于帧间最小间隔 */
} ZdtBus_t;
```

```c
/* 把 n 条「不含地址前缀的完整子命令」拼成一条 0xAA 广播帧 */
uint16_t Zdt_BuildMulti(uint8_t *o, const uint8_t *const *sub, const uint16_t *sub_len, uint8_t n);
```

### 4.5 总线层 API

```c
int ZdtBus_Init (ZdtBus_t *bus, ZdtPort_t *port, ZdtMotor_t *pool, uint8_t cnt);
int ZdtBus_Post (ZdtBus_t *bus, const uint8_t *frame, uint16_t len);  /* 入队，不阻塞 */
int ZdtBus_Tick (ZdtBus_t *bus);   /* 1 ms 周期调用：出队发送、维持帧间间隔 */
```

### 4.6 ⚠️ 三个必须写进库的坑

**坑 1：帧间粘包**
手册 3.5.2 原文：「**每条命令发送完后，要延时几毫秒，防止命令之间粘包失效**」。
`ZdtBus_Tick()` 必须保证相邻两帧之间有 **≥ 2 ms** 间隔（保险起见取 3–5 ms）。用 `last_tx_tick` 做闸门。这是新手最容易忽略、且现象最诡异（命令时灵时不灵）的问题。

**坑 2：Emm 固件的加速度是个「反向」参数**

```
t₂ − t₁ = (256 − acc) × 50 µs    每 (256−acc)×50µs 转速变化 1 RPM
```

- **`acc = 0` 表示不走加减速曲线，直接以设定速度启动** —— 底盘上会猛地一顿，机械冲击很大。
- **`acc` 越大，加速越快**（和直觉相反）。
- 换算：从 0 加速到 V RPM 需要 `V × (256−acc) × 50µs`

  | acc | 加速到 1500 RPM 耗时 | 评价 |
  |---|---|---|
  | 10 | 1.85 s | 慢到不可用 |
  | 200 | 0.42 s | 太肉 |
  | 250 | 45 ms | 底盘合适 |
  | 253 | 23 ms | 偏激进 |
  | 255 | 7.5 ms | 近乎直启，伤机械 |

  **底盘建议 248–252，机械臂建议 240–248（更柔和）。** 很多人随手填个 10，然后困惑为什么车慢得像蜗牛——就是这个原因。

**坑 3：Emm 固件「速度值缩小 10 倍」开关**
配置命令 `4F 71`，默认 `00`（关闭），表示速度值是**整数 RPM**（0–3000）。
如果被使能成 `01`，输入 1 表示 **0.1 RPM**，所有速度值含义全部变 10 分之 1。
**库里必须硬编码假定这一项为 `00`，并在 Bring-up 时用命令显式写死**，否则现场换个电机就出现「速度差 10 倍」的灵异事件。

### 4.7 数据格式约定

- **字节序：全部大端（Big-Endian）**。
  验证：手册示例 `01 CD 01 01 FF 01 FA 27 10 00 00 8C A0 00 00 07 D0 6B`，位置字段 `00 00 8C A0` = `0x8CA0` = 36000 → 保留一位小数 → **3600.0°** ✓
  速度字段 `27 10` = `0x2710` = 10000 → **1000.0 RPM** ✓
- **校验码：默认固定 `0x6B`**（`通讯校验方式 = 00`）。库另外实现 XOR / CRC-8 / Modbus 三种，通过 `csum_mode` 切换。
- **单位约定（库对外接口一律用工程单位，内部负责编码）**：
  | 物理量 | 库接口单位 | 协议编码 |
  |---|---|---|
  | 速度 | RPM (float) | Emm 速度模式：整数 RPM，2 B |
  | 位置 | 脉冲 (int32) | 4 B，3200 脉冲/圈 @ 细分 16、1.8° 电机 |
  | 位置（备选） | 度 (float) | 由脉冲换算：`pulse = deg / 360 × 3200` |
  | 加速度 | 档位 0–255 (uint8) | 1 B |
  | 时间 | ms (uint32) | 4 B |

  > 建议**对外统一用「关节角度（度）」，库内部转脉冲**，这样机械臂代码里不用到处出现 3200。

### 4.8 多电机命令打包示例

**底盘 4 轮一次下发**（Emm 速度模式，每轮 8 字节，共 37 字节）：

```
00 AA 00 25 | 02 F6 <dir> <spdH> <spdL> <acc> 00 6B
            | 03 F6 <dir> <spdH> <spdL> <acc> 00 6B
            | 04 F6 <dir> <spdH> <spdL> <acc> 00 6B
            | 05 F6 <dir> <spdH> <spdL> <acc> 00 6B
            | 6B
```

**三轴臂一次下发**（Emm 位置模式，每轴 13 字节，共 44 字节）：

```
00 AA 00 2C | 06 FD <dir> <spdH> <spdL> <acc> <pulse×4> 01 00 6B
            | 07 FD ...
            | 08 FD ...
            | 6B
```

- `AA` = 多电机命令功能码；`00` = 广播地址
- `00 25` = **整帧总字节数**（含 `00 AA 长度 校验` 自身）。手册示例 `00 AA 00 22` 对应 34 字节整帧，已验证。
- 末尾 `6B` = 整帧校验码

> ⚠️ 多电机命令**不支持 Modbus-RTU 协议**，所以校验方式必须保持自由协议（`6B`/XOR/CRC8）。

## 5. 运动控制设计

### 5.1 麦轮底盘

X 型布局（滚子呈 X 交叉，最常见），底盘速度 `(vx, vy, ω)` → 四轮线速度：

```
v_FL = vx − vy − (Lx + Ly)·ω
v_FR = vx + vy + (Lx + Ly)·ω
v_RL = vx + vy − (Lx + Ly)·ω
v_RR = vx − vy + (Lx + Ly)·ω
```

其中 `Lx` = 半轴距（前后），`Ly` = 半轮距（左右）。

再转成电机 RPM：`rpm = v_wheel / (2π·r_wheel) × 60 × gear_ratio`

> ⚠️ **符号约定必须实车标定**。麦轮的正负号取决于：滚子 45° 朝向、电机安装方向、以及每个电机自己的 `修改电机运动正方向` 配置。建议做法：
> 1. 先在 STM32 里做个**开环调试模式**：能单独给某个轮发 ±300 RPM；
> 2. 逐个验证「正命令 → 车往哪个方向走」；
> 3. 把实测符号写进一张 `wheel_sign[4]` 表，而不是散落在代码里。
>
> 这半天的工作量能省掉后面几天的抓瞎。

- **控制周期：100 Hz**（10 ms）。低于 50 Hz 操作手感会明显迟钝。
- **同步**：4 个轮用 `ZDT_EXEC_SYNC` 缓存 + 广播 `00 FF 66 6B` 触发，保证同时启动。虽然闭环速度控制本身能纠偏，但直线行驶时同步能显著减小跑偏。
- **限幅**：所有轮速统一按最大可用值等比例缩放（`scale = min(1, max_rpm / max(|rpm_i|))`），保证方向不失真 —— 直接对单个轮截断会让车走歪。

### 5.2 三轴臂

| 轴 | 地址 | 建议回零模式 | 建议 acc | 说明 |
|---|---|---|---|---|
| Yaw | `0x06` | `00` 单圈就近 | 240–248 | 编码器绝对角度，无需限位开关 |
| 升降 | `0x07` | `03` 限位 / `02` 碰撞 | 240–248 | 有微动开关就用限位，更干净 |
| 伸缩 | `0x08` | `03` 限位 / `02` 碰撞 | 240–248 | 同上 |

- 一律使用**绝对位置模式**（运动模式 `01`，相对坐标零点），便于重发与幂等。
- 上位机下发的是**关节角度**，由 STM32 或树莓派做逆运动学。
- ⚠️ **无反馈下的到位判断**：STM32 侧按 `加速段 + 匀速段 + 安全余量` 估算超时时间，超时即认为到位（或报错）。这个估算值需要实测标定，写进配置表。
- **软限位**：库里对每个轴做角度钳位，防止上位机发疯指令撞坏机械结构。

### 5.3 舵机夹爪

- TIM 通道输出 50 Hz PWM，脉宽 0.5–2.5 ms 对应 0–180°。
- ⚠️ 舵机上电瞬间会猛冲到默认位置，机械设计上要么留出自由行程，要么让上位机在回零完成后才发目标角度。
- 若夹持力不足，考虑换成带力反馈的舵机，或后续升级为 X 固件 Y42 + 力矩模式（夹紧后维持电流并主动返回 `F5 + 9F`，是专门为夹爪设计的）。

## 6. STM32 ↔ 树莓派 自定义串口协议

### 6.1 帧格式

```
┌──────┬──────┬─────┬──────┬──────┬───────────┬────────┐
│ SOF1 │ SOF2 │ LEN │ SEQ  │ CMD  │   DATA    │ CRC16  │
│ 0xAA │ 0x55 │ 1 B │ 1 B  │ 1 B  │  LEN−3 B  │  2 B   │
└──────┴──────┴─────┴──────┴──────┴───────────┴────────┘
                  LEN = CMD(1) + DATA(N) + CRC(2)
```

- CRC16-MODBUS，多项式 `0xA001`，初值 `0xFFFF`
- 定长头 + LEN 字段，配合 SOF 双字节，帧同步可靠

### 6.2 命令表

**树莓派 → STM32**

| CMD | 名称 | DATA | 频率 |
|---|---|---|---|
| `0x01` | `CMD_VEL` | `int16 vx(mm/s)`, `int16 vy(mm/s)`, `int16 wz(mrad/s)` | 50–100 Hz |
| `0x02` | `CMD_ARM_TARGET` | `uint8 axis(1-3)`, `int32 deg×100` | 事件 |
| `0x03` | `CMD_ARM_HOME` | `uint8 mask`（bit0-2 = yaw/lift/ext） | 事件 |
| `0x04` | `CMD_GRIPPER` | `uint8 pos(0-180)` | 事件 |
| `0x05` | `CMD_ENABLE` | `uint8 en`, `uint8 mask` | 事件 |
| `0x06` | `CMD_ESTOP` | — | 事件，最高优先级 |
| `0x10` | `CMD_HEARTBEAT` | — | 1 Hz |

**STM32 → 树莓派**

| CMD | 名称 | DATA | 频率 |
|---|---|---|---|
| `0x81` | `RPT_ODOM` | `int32 x(mm)`, `int32 y(mm)`, `int16 theta(mrad)` | 50 Hz |
| `0x82` | `RPT_JOINT` | `int16[3] deg×100`, `uint8 gripper` | 20 Hz |
| `0x83` | `RPT_STATUS` | `uint8 state`, `uint8 err_code`, `uint8 motor_online_mask` | 10 Hz |
| `0x84` | `ACK` | `uint8 ack_cmd`, `uint8 result` | 事件 |

> ⚠️ `RPT_ODOM` 依赖 §3.5 的决策。如果走纯 TX-only，这一项只能填 0 或省略。

### 6.3 关键设计点

- **STM32 → 树莓派这条链路是双向的**（Pi 要发指令、STM32 要回里程计），所以 USART1 的 TX/RX 都要接。这是**另一条独立的串口**，和电机总线无关。
- **心跳**：STM32 若 500 ms 收不到 `CMD_HEARTBEAT` 或 `CMD_VEL`，主动进入安全状态（电机减速停止）——这是最后一道防线，独立于电机自带的心跳保护。
- **波特率建议 460800**。STM32→Pi 的遥测在 115200 下会占到 60%+，不够用。

### 6.4 ROS2 侧节点设计

```
ros2_ws/src/zdt_bridge/
├── zdt_bridge/
│   ├── protocol.py        # 帧编解码 + CRC16
│   ├── serial_node.py     # 串口收发线程
│   └── bridge_node.py     # ROS 接口
├── launch/
└── config/
```

**接口暴露**：

| 方向 | 名称 | 类型 |
|---|---|---|
| 订阅 | `/cmd_vel` | `geometry_msgs/Twist` |
| 订阅 | `/arm/joint_command` | `sensor_msgs/JointState` |
| 发布 | `/odom` | `nav_msgs/Odometry` |
| 发布 | `/joint_states` | `sensor_msgs/JointState` |
| 发布 | `/motor_status` | `std_msgs/String`(JSON) 或自定义 msg |
| 发布 | TF `odom → base_link` | `tf2` |

## 7. 安全设计（无反馈场景下尤其重要）

| 层级 | 措施 |
|---|---|
| 电机级 | **心跳保护**：底盘 200 ms / 臂 500 ms，断联自动急停 |
| 电机级 | 过热/过流保护阈值配置（`5.6.23`，默认 100 ℃ / 6600 mA / 1000 ms） |
| 链路级 | STM32 侧 500 ms 收不到 Pi 心跳 → 底盘减速停止、臂保持 |
| 固件级 | 上电默认所有电机**不使能**，收到上位机指令后才使能 |
| 固件级 | 软件限幅：速度 ≤ `max_rpm`、关节角度在软限位内 |
| 硬件级 | 急停按钮（常闭）→ 直接切断电机使能 / 驱动电源 |
| 硬件级 | 底盘前方红外/超声急停（可选，比赛常见要求） |
| 流程级 | 任何异常（CRC 错、超时、状态位异常）→ 记录 + 决定是否 `CMD_ESTOP` |

**上电时序**（建议固化为状态机）：
```
上电 → 电机不使能 → 等待 Pi 连接 → 逐个使能 → 触发回零 → 固定延时 → 位置清零 → READY
                                                                    ↓ 失败
                                                              FAULT (等待上层复位)
```

## 9. 硬件资源评估（STM32F103C8T6）

| 资源 | 数量 | 分配 |
|---|---|---|
| USART1 (APB2) | 1 | ↔ 树莓派（TX+RX 都要接） |
| USART2 (APB1) | 1 | ↔ 7 个电机总线（TX 必需，RX 建议预留） |
| USART3 (APB1) | 1 | 调试口 / 备用（可拆成臂的独立总线，见下） |
| CAN1 | 1 | 空闲，未来可换 CAN 版电机 |
| TIM2/3/4 | 3 | 1 个做 1 ms 系统节拍，1 个做舵机 50 Hz PWM |
| Flash 64 KB | — | 电机库 + 运动学 + 协议，实际占用预计 < 20 KB，**充裕** |
| RAM 20 KB | — | 发送队列 + 状态结构，预计 < 4 KB，**充裕** |

> 💡 **备选方案：底盘和臂分两条总线**（底盘走 USART2、臂走 USART3）。
> 好处：底盘 100 Hz 的实时流量不会和臂的指令互相抢带宽；一条总线故障不会全车瘫痪；调试时分开抓包更清晰。
> 代价：多一对走线。
> **建议**：先按单总线实现（库的 `ZdtBus_t` 天然支持多实例，改造成本≈0），如果实测发现带宽或干扰问题，直接开第二条总线即可 —— 这是这套分层架构白送的红利。

> **M0 和 M1 是地基**，尤其 M0 —— 那一步做错，后面所有诡异现象都会指向它。

**Emm 位置模式参数范围**
- `dir`：`00`=CW，`01`=CCW
- `spd`：`0000–0BB8`，即 0–3000 RPM
- `acc`：`00–FF` 档位，`00` = 不使用加减速曲线（直接启动），越大加速越快
- `p0..p3`：32 位脉冲数，3200 脉冲/圈（1.8° 电机 @ 细分 16）
- `mode`：`00` 相对上次目标 / `01` 绝对零点 / `02` 相对当前位置
- `sync`：`00` 立即执行 / `01` 缓存等同步触发
