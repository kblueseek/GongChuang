## 0. 总览：四层架构

```
┌─────────────────────────────────────────────────────────────────────────┐
│ 第一层 上位机（笔记本或树莓派桌面，tkinter）                                │
│   motion_gui.py：动作序列/雷达地图/节点任务/PID调参 四页签                   │
│   规划 A*（转向惩罚+入场朝向）→ 组装指令序列 → 校验/预览 → 一键下发            │
└──────────────┬──────────────────────────────────────────────────────────┘
               │ ROS2/DDS（WiFi 局域网，同 ROS_DOMAIN_ID）
┌──────────────▼──────────────────────────────────────────────────────────┐
│ 第二层 树莓派 ROS2 节点（Ubuntu + ROS2 Lyrical）                           │
│   motion_planner：任务状态机，逐条执行指令序列（10Hz）                       │
│   ring_fix       ：圆环工位视觉矫正（calibrate 指令的执行者）                │
│   f407_bridge    ：话题 ↔ PiComm 帧双向桥 + 里程计修正偏移                   │
│   joy_control    ：USB 手柄 → 控制话题（带让位机制）                         │
│   （可选）ydlidar_ros2_driver / obstacle_detect / pid_tuner / gimbal_track  │
└──────────────┬──────────────────────────────────────────────────────────┘
               │ PiComm 协议（USART6 115200 有线，或 BLE 上行 + LoRa 下行）
┌──────────────▼──────────────────────────────────────────────────────────┐
│ 第三层 F407（FreeRTOS，C 固件）                                            │
│   底盘：位置环+航向环（200Hz）→ 麦轮逆解算 → ZDT 电机速度环（CAN）           │
│   云台：三轴位置环（200Hz）+ 限位/零点/松轴                                 │
│   遥测：里程计 50Hz / 状态 5Hz / 云台 20Hz 回传；离线自主失能                │
└──────────────┬──────────────────────────────────────────────────────────┘
               │ CAN 总线（4 轮 200Hz 速度指令 / 100Hz 编码器反馈）+ UART3 陀螺仪
┌──────────────▼──────────────────────────────────────────────────────────┐
│ 第四层 执行器                                                              │
│   4× ZDT 一体化无刷伺服轮（编码器 65536/圈，堵转保护，加速度斜坡）            │
│   3× 云台电机（yaw/lift/extend）＋ 夹爪/托盘/相机舵机 ＋ 补光灯 PWM          │
│   陀螺仪：MSP0G3507+XV7011 单轴（USART3 115200，200Hz）或 JY901S（宏切换）   │
└─────────────────────────────────────────────────────────────────────────┘
```

## 1. 通信链路

### 1.1 树莓派 ↔ F407（PiComm 协议）

帧格式：`AA 55 | LEN | SEQ | CMD | DATA | CRC16-MODBUS`。编解码两份实现：
`ros2_ws/src/f407_bridge/pi_comm.py`（在用的完整版）与 `comm/pi_comm.py`（脚本测试副本）。

**下行命令（树莓派 → F407）：**

| 命令 | 内容 | 频率/时机 |
|------|------|-----------|
| `0x01 CMD_VEL` | 车体速度 vx/vy/wz（int16 mm/s、mrad/s） | 手柄有输入才发（+回中补一帧零速） |
| `0x02/0x08 CMD_GIMBAL(_VEL)` | 云台单轴角度 / 速度模式 | 事件性 |
| `0x03 CMD_HOME` | 云台回零（位掩码） | 事件性 |
| `0x04/0x05/0x06` | 夹爪 / 托盘 / 相机舵机角度 | 事件性 |
| `0x07 CMD_ENABLE` | 整车使能/失能 | 事件 + 心跳周期重发 |
| `0x09 CMD_POSE` | **位姿目标** x/y/yaw（int32 mm + int16 mrad） | 位置闭环期间 10Hz 重发 |
| `0x0A CMD_LED` | 补光灯 0~100%（PWM 调光） | 事件性 |
| `0x0B/0x0C` | 云台限位 / 松轴 | 示教用 |
| `0x0D CMD_TUNE` | 在线调参（参数号 + float32） | 拖滑杆即下发 |
| `0x0E CMD_GIMBAL_ZERO` | 云台置零（位掩码） | 事件性 |
| `0x10 CMD_HEARTBEAT` | 心跳（保活） | **5Hz** |

**上行回传（F407 → 树莓派）：**

| 回传 | 内容 | 频率 |
|------|------|------|
| `0x81 RPT_ODOM` | 里程计 x/y/yaw | **50Hz** |
| `0x83 RPT_STATUS` | 整车状态/错误码/电机在线掩码 | 5Hz |
| `0x84 RPT_GIMBAL` | 云台三轴位置（相对零点，0.1°） | 20Hz |
| `0x85 RPT_TUNE` | 调参回显 | 事件性 |
| `0x86 RPT_GIMBAL_LIMIT` | 当前生效限位 | 2Hz |

**两条安全规则（写上层代码必须知道）：**
1. **心跳断 500ms → F407 自主失能**（latch，恢复后需重新使能）。
2. **任何 VEL 帧会立刻清除位姿闭环**（`PosTarget.Valid=0`）——所以走/转期间
   motion_planner 每 100ms 重发 POSE，手柄回中的零速帧也会打断自动导航。

**链路方式**（`f407_bridge` 参数）：`uplink/downlink ∈ wire | ble | rfcomm | lora`。
默认有线 `wire`（/dev/ttyAMA0）；整车无线 = BLE 上行 + LoRa 下行（见无线链路搭建.md）。
掉线自动重连，物理链路状态发 `/f407_online`、`/ble_connected`。

### 1.2 上位机 ↔ 树莓派

ROS2 DDS over WiFi（两边 `ROS_DOMAIN_ID` 一致）。上位机发 `/motion_load`（JSON 指令序列）、
`/motion_stop`、`/cmd_tune`、`/cmd_enable`、云台标定话题；订阅 `/odom`、`/motion_state`、
`/robot_status`、`/cmd_pose`（波形目标值）、`/gimbal_state`、`/gimbal_limits`、`/tune_state`、
`/f407_online`、**`/odom_shift`**（里程计被视觉矫正重置时同步平移场地锚点）。

### 1.3 F407 ↔ 电机 / 传感器

- **4 轮 CAN**：200Hz 速度广播（失能时也发 0 速锁轴）；编码器位置 100Hz 定时回传（0x36）。
- **陀螺仪 USART3 115200**：`RobotConfig.h` 的 `IMU_USE_MSPM0` 二选一——
  `1` = MSP0G3507+XV7011 单轴模组（上电自动设 200Hz 输出，零偏已扣除+判静锁零）；
  `0` = JY901S 九轴。驱动在 `ExHardware/MSPM0imu.c` / `JY901S.c`，统一出口 `Imu_t Imu`。
- 手柄走 **USB → 树莓派 joy_node**（不是直连 F407）；USART2 蓝牙是备用遥控通道（默认关）。

### 1.4 里程计修正（/set_odom 机制）

`ring_fix` 视觉对准后发 `/set_odom`，`f407_bridge` 记录偏移（绝对量）：
- `/odom` 上报时 **加偏移**：`odom' = t + R(Δθ)·raw`
- `/cmd_pose` 下发时 **减偏移**（F407 始终活在原始里程计系，ROS 侧统一活在修正系）
- 同时发 `/odom_shift`，上位机把"车起点"锚点做同样平移 → **地图不跳变**
- F407 重启（掉线恢复）→ 偏移自动清零（保守策略）

## 2. 上位机 motion_gui.py

四页签 GUI（启动见 `scripts/run_gui.sh`，需图形界面/VNC；也有 `windows_preview` 离线预览）。

### 2.1 坐标系与标定

- **场地系**（mm/°，画地图用）↔ **里程计系**（m/rad，下发/显示用）双向换算：
  `p_odom = R(-dq)·(p_field − start_field) + start_odom`，
  `dq = robot_start.yaw − odom_start.yaw`。
- `odom_start`：第一次收到 /odom 且车在起点附近自动锁存，或手动点
  【此刻车在【车起点】→ 标定里程计】。换陀螺仪/断电重启后必须重新标定。
- 鼠标悬停/目标点/下发的 goto 全部用里程计口径。

### 2.2 规划器（mapping.py）

1. 车道掩码按车半径**腐蚀**（走不通按 1.0→0.5 六档退让重试）；
2. **A\***（默认沿格中线模式 4 连通；关掉"沿格中线"则 8 连通+斜切）：
   代价 = 距离 + 中线偏离 bias + **转向惩罚**（`DEFAULT_TURN_PENALTY_MM=400`，
   换方向加等效距离，等距自动选少转向的）+ **入场朝向**（每段以"上一段作业朝向"
   为首步方向计罚，顺向进场不拧角度）；
3. 后处理：中线模式 `snap_path`（吸附格中线去抖动）+ `simplify_path` 去共线点；
   非中线模式 `shortcut_path` 视线拉直；`clearance_mm` 报告最小障碍余量。

### 2.3 九点任务组装（`_build_mission_commands`）

- 车不在启停区：先规划"先去第 1 个节点"预段；
- 车在启停区：**发车/停车走横移+直行**（启停区角上 300×300 转斜角会出界，
  用 `_strafe_move_pair` 把位移拆成 strafe+move 两条，零转向），中段从 E5/E1
  格子中心重新规划，绕开角上矩形线；
- 每段终点带作业朝向（机械臂朝工位中心：`_outward_yaw`，角度来自 approach 偏移，
  所以常是小数）；
- 【预览完整序列】把组装结果填进动作序列页只看不发，检查无误再执行。

### 2.4 波形（PID 页右侧）

位置环 X/Y、转向环、云台环、**XY 轨迹**（x/y 等比例，按校准 dq 旋转到场地朝向）。
虚线 = 目标（/cmd_pose），实线 = 实际（/odom）。

### 2.5 在线调参

拖动即下发 `/cmd_tune`（19 个参数：三轴最大速度、单轮限速、位置环/转向环 PID、
云台 yaw/lift/extend **三环独立** PID，编号 0x0B~0x13），407 回显后状态栏显示
"407 已确认"；407 重连自动整套重发。云台区支持
设零点 / 下发限位 / 松轴（与状态屏同一套话题）。

## 3. motion_planner 状态机（指令执行核心）

10Hz tick；从"当前里程计位姿"出发，把相对指令（move/strafe/turn）累计成绝对
目标位姿 (tx,ty,tyaw) 发 `/cmd_pose`（Pose2D），按 /odom 判到位，逐条推进。

### 3.1 执行策略（走/转分离）

每条 goto/move/strafe：**行进段**（目标 yaw 锁在出发朝向，只平移）→ 位置到位后
停稳 `turn_settle_s`（默认 0.3s）→ **原地转向**到目标 yaw → 连续 `turn_hold_s`
稳定才放行。到位容差 2cm/3°，单阶段超时 20s（超时停车交还手柄）。

### 3.2 指令集

`move/strafe/turn/goto(x,y,yaw,arrive_yaw)/gimbal/gripper/plate/cam/enable/delay/comment`
+ 复杂动作：
- `pick/place`：加载时展开成基本指令宏（张爪→安全位→下降→夹紧/张开→抬起）；
- `script`：启动任意程序（可等待/后台/超时）；
- `align`：跑程序读回 JSON {dx,dy,dyaw} 叠加修正目标；
- `vision_pick`：跑视觉程序，JSON 给抓取角后插 pick 宏；
- `calibrate {x_m,y_m}`：**圆环工位视觉矫正**（见 §4），失败/超时跳过不中断。

### 3.3 手柄让位

执行序列期间 10Hz 发 `/motion_active=True`，joy_control 收到后除"失能"外全部
让位；0.6s 没收到自动恢复手动（防本节点崩溃锁死手柄）。

## 4. ring_fix 节点（视觉矫正位置）

`calibrate` 指令的执行者（launch 已含，触发时才开摄像头，平时不占 /dev/video0）：

1. 收 `/ring_fix/target`（中间圆环的里程计坐标）→ 开摄像头（V4L2/MJPG 1280×720，
   畸变矫正映射与 vision/main.py 同一套配置）；
2. 逐帧跑 `vision/ring_station_detector.py` 三环检测，取检测器的底盘纠偏量
   （依赖配置里的 `chassis_image_to_motion` 3×3 矩阵），裁小步（≤40mm/≤4°）发
   `/cmd_pose`，周期重发保持（F407 位姿目标 ~100ms 过期）；
3. 纠偏量连续 3 帧 < 4mm/1.5° → 对准：发 `/set_odom`（圆环坐标 + 对准偏移
   `align_offset_x/y_m`，可选 `align_yaw_deg` 连航向一起修），再回 `/ring_fix/result`；
4. motion_planner 收到结果把 tx/ty/tyaw 同步到修正后坐标系，任务继续。

前提：触发前云台/相机摆到参考姿态、vision/main.py 没占用摄像头、纠偏矩阵已标定。

## 5. joy_control 手柄

USB 手柄 → `/joy` → 本节点 → `/cmd_vel`（速度模式，非线性死区）、`/cmd_enable`
（B 失能/Start 使能）、`/cmd_servo`（夹爪开关节：ROS 参数 `gripper_open/close_deg`）、
`/cmd_gimbal_vel`（云台速度模式）等。`/motion_active=True` 期间全部让位（只保留失能键）。
注意：手柄发的 VEL 帧会清掉 F407 位姿闭环（§1.1 规则 2），所以松杆回中那帧零速
本身就完成"接管"。

## 6. F407 固件逻辑（`UniversalCar/`，FreeRTOS）

### 6.1 任务表

| 任务 | 周期 | 职责 |
|------|------|------|
| ChassisTask | **5ms (200Hz)** | 底盘全部：调参应用→航向环→位置环→里程计→麦轮逆解算→CAN 发送 |
| GimbalTask | 5ms (200Hz) | 云台三轴位置环 + 限位/零点/松轴处理 |
| ImuTask | 5ms | 陀螺仪数据 → `Imu_t`（解析在 USART3 中断） |
| ReceiveTask | 10ms | Pi 离线检测失能、遥测回传（odom 50Hz 等）、蓝牙接管 |
| DebugTask | 10ms | 调试变量打包 UART1 DMA 发送 |

### 6.2 底盘控制链（200Hz 每拍）

```
/cmd_pose 目标 (tx,ty,tyaw)
  │ 位置环：世界系误差 → PosPidX/Y（纯 P + 限幅 0.5m/s，可在线调）
  │        → 车体系速度（÷ CHASSIS_AXIS_GAIN_X/Y 各向异性补偿）
  │ 航向环：s_HeadingTarget（位姿模式 = POSE 的 yaw）↔ Imu.Yaw
  │        → HeadingPid（°误差→°/s，死区0.1°）→ Wz
  ▼
麦轮逆解算（实测几何：半轴距0.1075/半轮距0.11/轮半径0.039）
  → 等比例限速（单轮 MaxWheelRpm）→ CAN 200Hz 广播
执行器：ZDT 一体化伺服（内部速度/电流环，CAN 加速度斜坡 ZDT_WHEEL_ACC，堵转保护）
反馈：编码器 100Hz → 里程计（整数计数差分×轮径，按 Imu.Yaw 旋转到世界系累加）
```

- **失能不松轴**：每拍发 0 速锁轴；重新使能时清堵转标志。
- **IMU 离线**（200ms 无帧）：清航向 PID、Wz=0，不用陈旧角度。
- **在线调参**：串口中断只置版本号，ChassisTask 比对后重载 PID 增益（避免半状态），
  再 13 拍逐条回显。

### 6.3 云台逻辑（GimbalTask 200Hz）

三轴独立位置环（yaw/lift/extend，PID 参数在线可调 `0x0B~0x0D`）：
- 目标来自 `/cmd_gimbal`（位置模式，速度限幅）或手柄 `/cmd_gimbal_vel`（速度模式）；
- **零点**：`CMD_GIMBAL_ZERO` 把当前位置定义成 0（电机掉电不保存，每次上电要示教）；
- **限位**：软限位（示教下发，`0x0B`）+ 当前生效限位 2Hz 回传，状态屏/上位机同源；
- **松轴**：`0x0C` 释放保持力便于手拨（树莓派掉线自动恢复锁轴）；
- 回传三轴位置 20Hz（0x84，相对零点 0.1°）。

### 6.4 夹爪 / 托盘 / 相机 / 补光灯

- 三个舵机（夹爪=`0x04`、托盘=`0x05`、相机=`0x06`）走 `/cmd_servo` 整组下发，
  F407 直接映射 PWM 脉宽（0~180°→ SERVO_PULSE_MIN~MAX），无任何闭环；
  夹爪"开/合"语义在调用侧（motion_planner 宏默认 120°/35°，手柄参数
  `gripper_open/close_deg`）。
- 补光灯：LED PWM 调光（`0x0A`，0~100%），Led_Init 无论哪种控制源都初始化。

### 6.5 手柄备用通道（默认关闭）

USART2 可接 BLE 透传模块跑旧小程序文本协议（`BLE_CONTROL_ENABLE`），
树莓派离线时蓝牙接管整车；PiComm 蓝牙上行是另一条（`BLE_UPLINK_ENABLE`，二进制帧）。
日常手柄一律走 §5 的 USB 链路。

## 7. 端到端示例

**九点任务**：上位机【雷达/地图】扫障碍 →【节点动作序列】配动作 →【规划全程】
（A* 转向惩罚）→【预览完整序列】核对 →【▶ 执行】→ motion_planner 逐条跑
（含发车横移、每段顺向进场、工位作业宏）→ 到位视觉 calibrate 清零里程计漂移
→ 回程横移进启停区。

**视觉矫正**：序列执行到 `calibrate(-2.169,1.061)` → motion_planner 发目标 →
ring_fix 对位 → /set_odom 重置 → 上位机锚点随 /odom_shift 平移 → 后续 goto
自动活在修正坐标系。

## 8. 频率总表

| 链路 | 频率 | 方向 |
|------|------|------|
| 底盘/云台控制任务 | 200Hz | F407 内部 |
| 4 轮 CAN 速度指令 | 200Hz | F407→电机 |
| 编码器位置回传 | 100Hz | 电机→F407 |
| 陀螺仪 yaw | 200Hz（MSPM0）/ 模块默认 | →F407 |
| 里程计遥测 | 50Hz | F407→树莓派 |
| /cmd_pose 重发 | 10Hz | motion_planner→F407 |
| 心跳 + 使能重发 | 5Hz | bridge→F407 |
| 状态 / 云台 / 限位回传 | 5 / 20 / 2Hz | F407→树莓派 |
| 波形采样 | 10Hz | 上位机本地 |

## 9. 启动方式

```bash
bash scripts/run_car.sh     # 树莓派：f407_bridge + motion_planner + ring_fix + 扫码 + 手柄 + 状态屏
bash scripts/run_gui.sh     # 上位机 GUI（需图形界面）
python3 上位机/windows_preview/preview.py   # 本机离线预览（不连真车）
```

> 想调任何节点的参数（串口、波特率、视觉程序路径、放置位姿、扫码口……）：只改
> `ros2_ws/src/car_bringup/config/vehicle.yaml`（按节点名分节），重启 run_car.sh 生效。
