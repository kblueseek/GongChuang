# 无线链路搭建与联调（蓝牙上行 + LoRa 下行 + I2C 状态屏）

树莓派 5 和 F407 用**两套独立电源**，中间不共地、不接任何线，全部靠无线通信。

```
        ┌──────────── 树莓派 5 ────────────┐          ┌──────────── F407 ────────────┐
        │                                  │          │                              │
 手柄 ─►│ /joy → joy_control → /cmd_vel     │          │                              │
        │        ↓                         │  蓝牙    │   USART2 (PA2/PA3)           │
        │   f407_bridge ────────────────────┼─────────►│      └─ PiComm 指令           │
        │        ▲                         │  (上行)   │                              │
        │        │ /odom /robot_status     │          │                              │
        │        └─────────────────────────┼◄─────────┤   UART4 (PC10/PC11)          │
        │        LoRa 串口 (GPIO4/5)       │   LoRa   │      └─ 遥测 (只发)            │
        │                                  │  (下行)   │                              │
        │   I2C OLED (GPIO2/3) ← /odom 等   │          │                              │
        └──────────────────────────────────┘          └──────────────────────────────┘
```

**为什么这样分方向**

| 链路 | 方向 | 理由 |
|---|---|---|
| 蓝牙 | 树莓派 → F407（上行指令） | 指令量小、延迟敏感，BLE 有链路层重传，丢一帧履带就抖 |
| LoRa | F407 → 树莓派（下行遥测） | 遥测能容忍丢包，LoRa 距离远；**只发不收**就不用来回切半双工 |

两条链路跑的是同一套 PiComm 二进制帧（`AA 55 | LEN | SEQ | CMD | DATA | CRC16`），
所以协议代码两端完全复用。

## 一、接线

### 1. F407 侧

| F407 引脚 | 接哪 | 说明 |
|---|---|---|
| PA2 (USART2_TX) | 蓝牙模组 RXD | 115200 |
| PA3 (USART2_RX) | 蓝牙模组 TXD | 115200 |
| PC10 (UART4_TX) | LoRa 模组 RXD | 115200 |
| PC11 (UART4_RX) | LoRa 模组 TXD | 当前不用，接上无妨 |
| 3.3V / GND | 两个模组 VCC/GND | ⚠️ 模组是 3.3V 逻辑，**不要接 5V** |

> LoRa 模组峰值发射电流较大，建议在 VCC 就近加 **100µF + 0.1µF** 电容，否则容易复位。

### 2. 树莓派侧

| 树莓派引脚 | 物理脚 | 接哪 |
|---|---|---|
| GPIO4 (UART2_TX) | 7 | LoRa 模组 RXD |
| GPIO5 (UART2_RX) | 29 | LoRa 模组 TXD（当前不用） |
| GPIO2 (I2C1_SDA) | 3 | OLED SDA |
| GPIO3 (I2C1_SCL) | 5 | OLED SCL |
| 3.3V / GND | 1 / 6 等 | 两个模组 + 屏幕供电 |

> 树莓派和 F407 **不要共地**，也不要接 USART6 那两根线。需要排查时才临时接。

## 二、LoRa 模组设置（DX-LR22-433T22D）

两块模组必须是**同一个信道、同一档空中速率**，串口波特率也要和代码一致。

你目前已经设好：`LEVEL7` + `CHANNEL00`，**串口 115200 8N1**，
F407 侧 `RobotConfig.h` 里 `LORA_UART_BAUD 115200`、树莓派 launch 里
`lora_baudrate: 115200` 都与之一致。**三边必须完全相同**，差一档就是全乱码。

如果要复核，用 USB-TTL 接模组，串口助手发（注意：先用模组**当前**的波特率连上，
进 AT 后再改；出厂默认是 9600）：

```
+++            → 回 +OK，进入 AT 模式（3 秒内没有下一步会自动退出）
AT+BAUD?       → 查串口波特率；AT+BAUD7 = 115200，AT+BAUD3 = 9600
AT+LEVEL7      → 空中速率档位 7（62500 bps）
AT+CHANNEL00   → 信道 0（433.15 MHz）
AT+MODE0       → 透明传输模式
AT+SLEEP2      → 高效模式（推荐）
AT+RESET       → 生效
```

> **改波特率要三边同时改**：模组 AT 设置、F407 的 `LORA_UART_BAUD`、树莓派 launch 的
> `lora_baudrate`（以及 `scripts/test_wireless.py --baud`）。改完模组一定要 `AT+RESET`，
> 串口助手也要换成新波特率才能看到回显。

## 三、树莓派系统配置

```bash
cd ~/你的仓库/raspberrypi
sudo bash scripts/setup_pi.sh
sudo reboot
```

脚本做的事：

1. 装 `python3-bleak`、`python3-luma.oled`、`python3-pil`、`i2c-tools`、`bluez` 等；
2. 把用户加进 `dialout i2c gpio bluetooth` 组；
3. 改 `config.txt`：
   - **注释掉 `dtoverlay=disable-bt`**（上行要用树莓派自己的蓝牙）；
   - 打开 `enable_uart=1`（有线备用）；
   - 加 `dtoverlay=uart2-pi5`（Pi5）或 `dtoverlay=uart2`（Pi4 及以下），把 **GPIO4/5 变成 UART2**；
   - 加 `dtparam=i2c_arm=on`。

重启后核对：

```bash
ls /dev/ttyAMA*        # 新增的那个就是 LoRa 串口（Pi5 一般是 /dev/ttyAMA2）
i2cdetect -y 1         # 应看到 0x3C（OLED）
bluetoothctl show      # Powered: yes，说明树莓派蓝牙正常
```

如果 `/dev/ttyAMA*` 里没有新增项，或者不确定 LoRa 该用哪个，用 `dmesg | grep -i ttyAMA`
看内核给 UART2 分配了哪个名字，然后把 launch 里的 `lora_device` 改成它。

> **Pi 5 的 overlay 名字**：Pi 5 用的是 RP1 芯片，UART 叠加层带 `-pi5` 后缀
> （`uart0-pi5` … `uart4-pi5`）。如果 `uart2-pi5` 报"overlay 不存在"，先用
> `ls /boot/firmware/overlays/ | grep uart` 看实际有哪些文件，再按名字替换。
> 旧机型（Pi 4 及以下）不加后缀，就是 `dtoverlay=uart2`。

## 四、F407 固件开关

`UniversalCar/Core/Inc/RobotConfig.h`：

```c
#define BLE_UPLINK_ENABLE    1     // USART2 = 蓝牙上行（PiComm 二进制帧）
#define LORA_DOWNLINK_ENABLE 1     // UART4  = LoRa 遥测下行
#define LORA_UART_BAUD       115200 // 必须与 LoRa 模组串口波特率一致
#define PI_CMD_TIMEOUT_MS    500   // 500ms 没收到指令 → 底盘停车
#define PI_RPT_FREQ_HZ       20    // 里程计 20Hz
#define PI_STATUS_FREQ_MS    200   // 状态 5Hz
```

几点说明：

- 遥测是 **20Hz 里程计 + 5Hz 状态**。115200 下一帧 17 字节约 1.5ms，串口完全吃得下；
  真正的上限是**空中速率**（LEVEL7 ≈ 62500bps），20Hz 已用掉不到 5%，还有余量。
- UART4 用**中断发送**，任务不会被 18ms 的发送卡住，底盘 5ms 控制周期不受影响。
- `BLE_CONTROL_ENABLE` 保持 `0`：那是旧的微信小程序文本协议，现在 USART2 走二进制 PiComm。

## 五、联调三步走

### 第 1 步：只验证 LoRa 下行（大约 30 秒）

F407 上电，树莓派上：

```bash
python3 scripts/test_wireless.py --no-ble          # 波特率默认已是 115200
```

应持续打印：

```
[OK ] odom   x=+0.000m y=+0.000m yaw=+0.000rad
[OK ] status state=1 err=0 motor=0x7F
```

看不到的话按顺序查：模组是否上电（灯）→ 两边 LEVEL/CHANNEL 是否一致 →
F407 的 PC10 是否接到模组 RXD → `lora_device` 是否指对。

### 第 2 步：加蓝牙上行

```bash
python3 scripts/ble_scan.py            # 先看清 F407 蓝牙模组的地址/名字
python3 scripts/test_wireless.py --ble-address AA:BB:CC:DD:EE:FF
```

点亮后脚本会每 200ms 发心跳，LoRa 那边继续打印回传。
此时屏幕上的 `state` 应该保持 1（READY），不会掉回 0。

> 没指定 `--ble-address` 时脚本会自己扫，扫到多台设备会在日志里列出清单。

### 第 3 步：起 ROS

```bash
source /opt/ros/lyrical/setup.bash
source ros2_ws/install/setup.bash
ros2 launch lidar_bringup car_only.launch.py
```

`car_only` 已经包含 **桥接 + 状态屏 + 运动规划 + joy_node + joy_control**，不用另开终端。
（也可以直接 `bash scripts/run_car.sh`。）

操作：手柄 **start** 使能，左摇杆前后、右摇杆左右、L2/R2 左右转。

> 转向是"推着转、松手停"：F407 把 L2/R2 的角速度积分成目标航向，松手后
> 航向 PID 会保持住新的朝向；直行时也会自动纠偏。

⚠️ 蓝牙断过之后 F407 会自主失能（安全设计），重连后需要**再按一次 start** 使能。

## 六、状态屏

`status_display_node` 订阅 `/odom`、`/robot_status`、`/f407_online`、`/ble_connected`、`/joy`，画面：

```
F407 ON   BLE OK  PAD
X  +1.234 m
Y  -0.056 m
YAW +45.3 deg
READY  M7F
ERR 0x00
```

**1.96 寸屏大概率是 160x80**，如果画面只显示左上角一块或者整体偏移，
在 launch 里把参数改成 `{'width': 160, 'height': 80}`；SH1106 的屏把 `controller` 改成 `sh1106`。

屏幕只是"看板"，画不出来不影响开车，日志里会有 `OLED 初始化失败` 的提示。

## 七、常见问题

| 现象 | 检查 |
|---|---|
| 扫描不到任何 BLE 设备 | `sudo systemctl status bluetooth`；`bluetoothctl show` 里 Powered 是否为 yes；`config.txt` 里是否还有 `dtoverlay=disable-bt` |
| 蓝牙连上但车不动 | `/cmd_vel` 有没有发；F407 是否使能（手柄 start）；`/f407_online` 是否为 true |
| 蓝牙连上、指令发出，F407 没反应 | 模组串口波特率是否和 USART2 的 115200 一致（很多 JDY/HC 模组出厂是 9600，要用 AT 改成 115200，或把 `MX_USART2_UART_Init` 改成 9600） |
| 车动一下就停，反复顿挫 | 心跳没发出去 → 蓝牙断开；`ros2 topic echo /ble_connected` |
| LoRa 一直没回传 | 波特率/信道/空中速率不一致（本项目统一 **115200**）；PC10 与模组 RXD 接反；模组供电不足 |
| 坐标一直是 0 | 没收到里程计；`ros2 topic hz /odom` 看频率 |
| 屏幕全黑 | `i2cdetect -y 1` 有没有 0x3C；分辨率参数是否和屏一致；VCC 是否 3.3V |
| 屏幕花屏/偏移 | `width/height` 不对（1.96 寸常见 160x80） |

## 八、参数速查

`f407_bridge_node`：

| 参数 | 默认 | 说明 |
|---|---|---|
| `uplink` | `ble` | `ble` / `rfcomm`（经典蓝牙 HC-05/06）/ `wire` |
| `ble_address` | 空 | 模组 MAC，留空自动扫描 |
| `ble_name` | 空 | 按名字关键字匹配 |
| `ble_write_uuid` | 空 | 留空自动探测 NUS / FFE1 / 第一个可写特征 |
| `downlink` | `lora` | `lora` / `wire` |
| `lora_device` | `/dev/ttyAMA2` | LoRa 串口 |
| `lora_baudrate` | `115200` | 必须与模组、F407 一致 |
| `wire_device` | `/dev/ttyAMA0` | 有线备用 |

`status_display_node`：

| 参数 | 默认 | 说明 |
|---|---|---|
| `i2c_port` / `i2c_address` | `1` / `0x3C` | I2C-1，常见地址 0x3C |
| `width` / `height` | `128` / `64` | 1.96 寸多半是 160×80 |
| `controller` | `ssd1306` | `ssd1306` / `ssd1315` / `sh1106` |
| `refresh_hz` | `2` | 刷新频率 |

## 九、经典蓝牙模组（HC-05 / HC-06）怎么办

这类模组是 **SPP 经典蓝牙，不是 BLE**，`bleak` 连不上。改成 rfcomm 方式：

```bash
# 配对一次（bluetoothctl）
bluetoothctl
> scan on
> pair AA:BB:CC:DD:EE:FF
> trust AA:BB:CC:DD:EE:FF
> quit

# 绑定成串口设备
sudo rfcomm bind 0 AA:BB:CC:DD:EE:FF 1
ls -l /dev/rfcomm0
```

然后把桥接节点改成：

```bash
ros2 run f407_bridge f407_bridge_node --ros-args -p uplink:=rfcomm
```

（模组本身的串口波特率仍要和 F407 的 USART2 一致：115200。）
