# 上位机使用说明（动作序列 + 雷达地图导航）

> 适用：`raspberrypi/上位机/`（`motion_gui.py` 二合一版本，2026-10）
> 硬件：树莓派 5（Ubuntu 26.04 / ROS2 Lyrical）+ F407 + D6 激光雷达 + TGZ 手柄
> 相关代码：[motion_gui.py](../上位机/motion_gui.py)、[mapping.py](../上位机/mapping.py)、
> [lidar_d6.py](../上位机/lidar_d6.py)、[field.json](../上位机/field.json)、
> [motion_planner](../ros2_ws/src/motion_planner/motion_planner/motion_planner_node.py)

---

## 1. 概述

### 1.1 能做什么

上位机是把两件事合并到同一个窗口里的工具：

1. **动作序列**：像写脚本一样编辑 `move / turn / goto / 云台 / 夹爪 / 舵机 …`，
   点一下整段或单条发给树莓派执行。云台、夹爪、相机这些非底盘动作走这条路。
2. **雷达地图导航**：连接 D6 激光雷达 → 扫几圈 → 识别障碍 → 在场地地图上
   点一个目标点 → A* 规划路径 → 自动拆成 `goto` 路点下发 → 小车自己开过去。

### 1.2 不做什么

| 不是 | 说明 |
|---|---|
| 不是"雷达建图" | 场地的形状（车道、黄块、工位）是用 `field.json` 的参数**画出来的**。雷达只能看到立起来的东西（圆柱、板子、人腿），看不到地面颜色。 |
| 不做视觉识别 | `vision/` 是另一个独立进程，本程序不依赖它。 |
| 不直接驱动电机 | 所有动作都发 `/motion_load` → `motion_planner` → `/cmd_pose` → `f407_bridge` → F407。上位机不碰串口（雷达串口除外）。 |
| 不做远程遥控 | 遥控是 `joy_control` 的事；上位机开车时手柄会自动让位。 |

### 1.3 数据流

```
 D6 雷达 ──USB 串口──> 上位机地图（扫描/识别/A*）
                            │
                            │ /motion_load  (String, JSON 指令数组)
                            ▼
                    motion_planner（状态机）
                            │ /cmd_pose (Pose2D)，每 0.1s 重发目标
                            ▼
                      f407_bridge ──PiComm AA 55──> F407
                            ▲
                            │ /odom (Odometry)  /robot_status (Int32MultiArray)
                            │ /motion_state (String)
                            │
 手柄 ──/joy──> joy_control ──/cmd_vel──> f407_bridge
                    ▲
                    │ /motion_active（上位机占权时手柄让位）
```

### 1.4 话题一览

| 话题 | 类型 | 方向 | 用途 |
|---|---|---|---|
| `/motion_load` | `std_msgs/String` | 上位机 → planner | 一整段 JSON 指令数组，收到就开始执行 |
| `/motion_stop` | `std_msgs/Bool` | 上位机 → planner | 停：锁定当前位置、交还手柄 |
| `/motion_state` | `std_msgs/String` | planner → 上位机 | 执行进度（"第 3/12 条 去 ..."、"已停止"） |
| `/motion_active` | `std_msgs/Bool` | planner → joy_control | True = 上位机在开车，手柄让位（10Hz 心跳，0.6s 断流自动恢复手柄） |
| `/odom` | `nav_msgs/Odometry` | bridge → 上位机 | 里程计位姿（米/弧度），也是 `goto` 的坐标基准 |
| `/robot_status` | `std_msgs/Int32MultiArray` | bridge → 上位机 | `[state, err, motor_mask]`，见 §12 |
| `/cmd_pose` | `car_interfaces/Pose2D` | planner → bridge | 绝对位姿目标 |
| `/cmd_gimbal` | `std_msgs/Float32MultiArray` | planner → bridge | `[yaw, lift, extend]` 度 |
| `/cmd_servo` | `std_msgs/Float32MultiArray` | planner → bridge | `[夹爪, 托盘, 相机]` 度 |

## 2. 启动

### 2.1 依赖

```bash
# Python 侧（当前树莓派上都已经装好：pyserial 3.5）
sudo apt install -y python3-tk python3-serial

# 串口权限：当前用户要在 dialout 组里
groups | grep dialout
```

ROS 侧需要先 `bash scripts/setup.sh` 构建过工作区（`f407_bridge`、`motion_planner`、
`joy_control`、`lidar_bringup`）。

### 2.2 启动顺序

```bash
# 终端 1：控制链路（f407_bridge + motion_planner + joy_control + 状态屏）
bash scripts/run_car.sh

# 终端 2：上位机界面
bash scripts/run_gui.sh
```

`run_gui.sh` 会做三件事：source ROS、处理 `DISPLAY` / `XAUTHORITY`（树莓派的
GNOME on Wayland 用 Xwayland，认证文件每次登录都变）、`cd 上位机 && python3 motion_gui.py`。

### 2.3 图形环境

- 必须在树莓派**本机桌面**或 **VNC** 里跑。SSH 直接跑会报 `no display name`。
- 通过 SSH 转发也可以：`ssh -X kbluepi@...` 后再 `run_gui.sh`（会慢一些）。
- 脚本连不上 X 时会给出明确提示，而不是甩一屏 traceback。
- 窗口按 1500×940 打开，1024×768 的屏上会被压缩；左栏页签自带滚动条。

### 2.4 退出与急停

- **急停**：底部【■ 停止（含导航）】或任意地方的 `■`，发 `/motion_stop`，
  planner 把当前位置设成目标让 F407 锁住，然后 `/motion_active=False` 交还手柄。
- 手柄 **B 键**是失能键，任何时候都有效（不受上位机占权影响）。
- 直接关窗口不会发停止；关闭前请先点停止。

## 4. 坐标系统（重点，务必看懂）

### 4.1 两套坐标

| | 场地系（场地/图纸） | 里程计系（F407 `/odom`） |
|---|---|---|
| 原点 | 场地正中心 | 上电时车的位置 |
| +x | 向右（图纸右） | 车头方向（上电时） |
| +y | 向上（图纸上） | 车左侧 |
| 单位 | mm、度 | m、弧度 |
| 角度 | 逆时针为正 | 逆时针为正 |
| 谁在用 | `field.json`、场地模型、地图绘制 | 界面读数、目标输入、`goto` 下发、规划结果 |

两套都是右手系，所以关系只是**一个平移 + 一个旋转**。

### 4.2 界面口径：你只看到里程计坐标

状态栏位姿、鼠标悬停、目标点读数、障碍列表、下发的 `goto`，全部是**里程计口径**
（米 / 度），和 `ros2 topic echo /odom` 一模一样。

地图仍然按场地正向画（黄块不歪、A1~E5 正对屏幕），场地↔里程计的换算在程序内部完成，
你对屏幕点一下就行。`field.json` 里的尺寸和安装位姿仍然是场地系 mm/度 —— 它们描述
的是场地本身，和里程计无关。

### 4.3 为什么每次上电要标定

F407 的里程计 yaw **不是从 0 开始的**：它直接用 JY901S 的绝对 yaw（`Imu.Yaw`），
上电读到多少就是多少；而 x/y 是编码器积分，上电为 0。

所以只知道"车起点在场地哪"还不够，还要知道"车起点对应的里程计 yaw 是多少"。
记号如下：

```
    rsx, rsy, rθ   = robot_start 的场地坐标/朝向
    osx, osy, oθ0  = 车起点对应的里程计位姿（标定出来的 odom_start）
    dq = rθ − oθ0                      // 两个坐标系的旋转差

场地 → 里程计：
    dx = fx − rsx,  dy = fy − rsy
    ox = osx + (dx·cos(dq) + dy·sin(dq)) / 1000
    oy = osy + (−dx·sin(dq) + dy·cos(dq)) / 1000
    oθ = fθ − dq

里程计 → 场地：
    dx = ox − osx,  dy = oy − osy
    fx = rsx + (dx·cos(dq) − dy·sin(dq)) · 1000
    fy = rsy + (dx·sin(dq) + dy·cos(dq)) · 1000
    fθ = oθ + dq
```

### 4.4 怎么标定

- **自动**：刚启动、第一次收到 `/odom` 且 `|x|<0.2m`、`|y|<0.2m` 时，自动把当时的
  `/odom` 位姿锁存为 `odom_start`。正常上电流程就是这种情况。
- **手动**：车已经动过、或者 GUI 是后启动的，把车**摆回车起点**，点
  【此刻车在【车起点】→ 标定里程计】。
- 标定值显示在紫色的 `里程计标定: (...)` 一行。
- **没标定时**：地图上的车不画、悬停显示"odom 未标定"、导航会拒绝下发。

### 4.5 什么时候必须重新标定

- F407 重新上电/复位（odom 归零）；
- 车被手动搬动过；
- 改了 `field.json` 的 `robot_start`，且车当时不在那个位置。

> 彻底去掉"每次标定"需要改 F407 固件：上电时把 `Imu.Yaw` 记成参考 0，
> 让 `/odom` 的 θ 从 0 开始。这会同时影响航向控制的 `TargetYaw` 语义，需要一起改。

## 5. 场地模型 `field.json`

所有尺寸单位 **mm**，角度 **度**。改完点界面上的【保存场地参数】写回文件，
下次启动生效（部分参数立即生效）。

### 5.1 字段表

| 键 | 当前值 | 含义 | 什么时候改 |
|---|---|---|---|
| `field.width_mm` / `height_mm` | 2400 / 2400 | 场地尺寸 | 场地换了 |
| `drivable.white` | `false` | `false`=只走灰色田字；`true`=除黄块全场可走 | 见 5.4 |
| `lane.width_mm` | 400 | 十字车道宽度 | 现场量 |
| `lane.ring_mm` | 550 | 外圈车道宽度（贴四面墙） | 现场量；`0`=只有十字 |
| `yellow_blocks.size_mm` | 450 | 黄块边长 | 现场量 |
| `yellow_blocks.gap_from_lane_mm` | 0 | 黄块内边离车道边的缝 | 一般 0 |
| `cell_grid.cols/rows/cell_mm` | 5/5/450 | 5×5 逻辑网格 | 和现场"第几格"的说法对齐 |
| `start_zones[]` | 2 个 300×300 | 启停区：可走、可放车/雷达 | 位置变了 |
| `work_zones[]` | 4 个 | 工位：`name/x/y/w/h/approach` | 位置变了 |
| `mission.route` | 9 个名字 | 任务路线，`START` = 雷达所在启停区 | 任务变了 |
| `mission.speed_mm_s` | 250 | 只用于估算全程时间 | 参考值 |
| `robot_start.x/y/yaw_deg` | 1000 / 1000 / 225 | 车起点（上电时车的场地位姿） | **必须和实际上电位置一致** |
| `lidar.port` | `/dev/ttyUSB0` | 雷达串口 | 换了 USB 口 |
| `lidar.baud` | 230400 | 波特率（D6 默认） | 一般不动 |
| `lidar.x/y/yaw_deg` | 1000 / 1000 / 225 | 雷达安装位姿（场地系） | 雷达装在车上时 = 车起点 |
| `lidar.angle_cw` | `true` | 设备角度顺时针为正（D6 如此） | 点云镜像时切换 |
| `lidar.mount` | `启停区1` | 标签，`START` 用它解析 | 和 `start_zones` 的名字对应 |
| `cylinder.diameter_mm` | 50 | 圆柱标准直径 | 障碍物换了 |
| `cylinder.radius_tol_mm` | 14 | 拟合半径容差 | 误检多/漏检时调 |
| `cylinder.min_points` | 4 | 判成圆的最少点数 | 同上 |
| `cylinder.blob_min_points` | 3 | 少于这个数当噪声 | 同上 |
| `cylinder.cluster_gap_mm` | 90 | 聚类连通阈值 | 同上 |
| `scan.revolutions` | 5 | 扫描圈数 | 想更稳就加大 |
| `scan.range_min_mm` / `range_max_mm` | 120 / 8000 | 距离过滤 | 近场地面回波多就加大 min |
| `grid.cell_mm` | 20 | 规划栅格精度 | 一般不动 |
| `robot.radius_mm` | 170 | 规划用的车半径（含余量） | 车/安全距离变了 |
| `corridor`（可选） | 默认 `true` | 启停区到车道自动补一条走廊 | 现场确认有灰色连接带时设 `false` |

> `cylinder.height_mm`、`lidar.height_mm`、`scan.min_intensity` 只是记录用，
> 程序目前**不参与计算**。

### 5.2 "田"字形是怎么来的

灰色可走区域 = **外圈**（贴四面墙、宽 `ring_mm`）+ **十字**（宽 `width_mm`），
黄块是禁行区。默认 `ring_mm=550`，正好把半场铺满：

```
半场 1200 = 200（半个十字）+ 450（黄块）+ 550（外圈）
```

所以四个黄块夹在十字和外圈之间，整个场地被"灰（田字）+ 黄"完全铺满，没有白区。

外圈不是贴墙的一圈细线，而是一整条可以开车的带。车在启停区（1000,1000）里，
启停区 300×300，正好落在 550 宽的外圈里。

### 5.3 5×5 逻辑格（A1~E5）

- 列 A~E 从左到右，行 1~5 从下到上；**A1 左下，E5 右上，C3 场心**。
- 格边长 450，5 格共 2250，两边各留 75。
- **B2 / B4 / D2 / D4 正好是四个黄块**，不可走，点它们会提示"目标被占住"。
- 格子只是**给人看的名字**，规划用的是 20mm 栅格。

### 5.4 关于【白区可走】

当前 `ring_mm=550` 时，外圈 + 十字已经把全场铺满，所以严格模式（白区不可走）
和"除黄块全场可走"**结果一样**，这个开关暂时没有区别。

只有把 `ring_mm` 改小、黄块和墙之间留出白区时，两种口径才有差别：
关 = 不压白区（按规则）；开 = 允许压白区绕障（临时救急）。

## 6. 雷达

### 6.1 D6 协议要点

一帧 = `AA 55 | M&T | LSN | FSA | LSA | CS | 3N 字节`，长度 `10 + 3N`。

- 距离：`Si_H × 64 + (Si_2nd >> 2)`，mm；
- 强度：`(Si_2nd & 3) × 64 + (Si_L >> 2)`；
- 角度：`FSA/128` 起，按 `(LSA−FSA)/(LSN−1)` 线性插值；
- 启动命令 `AA 55 F0 0F`，停止 `AA 55 F5 0A`；
- 设备角度**顺时针为正**，程序按 `angle_cw` 取反后用。

### 6.2 串口

- 默认 `/dev/ttyUSB0`，230400。界面会优先挑 CH340/CP210/FTDI 这类 USB 串口。
- 打不开时界面弹窗会给出具体错误（`Permission denied` → 加 `dialout` 组后重新登录）。
- **不要和 YDLIDAR X3 PRO 抢同一个口**：旧链路 `/dev/ydlidar` 是 115200，D6 是 230400，
  两者不能共用同一个串口设备（各插各的转接板、各用各的设备名就没问题）。

### 6.3 连接与模拟

- 【连接并开始】：打开串口（或启动模拟雷达），按钮变成【断开】。
- 【用模拟雷达】：没插雷达也能把整个流程跑通。它会按 `field.json` 的雷达位姿
  向几个虚拟圆柱打光线，输出和真雷达一样的数据。调界面、演示、教别人都用它。

### 6.4 安装位姿

- 雷达**装在车上**、原地扫描：点【雷达 = 车起点（雷达装在车上时用）】，
  三个数和 `robot_start` 一致。
- 雷达**固定在场边**：填实际场地坐标和 0° 朝向。
- 装车后点云和地图对不上？用 `◀ 15° / ◀ 5° / 5° ▶ / 15° ▶` 微调，
  调一次就会用原始回波立刻重算，不用重扫。

### 6.5 扫描

1. 车**保持静止**，视野里别站人（人腿会被当成障碍）。
2. 点【① 扫描建图（扫几圈后冻结）】。
3. 扫满 `scan.revolutions` 圈自动停，然后自动识别障碍。
4. 扫描期间只收数据、不识别；扫完**冻结**，避免比赛途中地图一直变。
5. 之后想重识别（比如改了检测参数）点【② 重新识别障碍】，不用重扫。
6. 【清空点云】清掉所有回波和障碍。

### 6.6 帧体检

地图左上角会显示 `帧体检：0.90°/点 正常（≈400 点/圈）`：

- **0.3 ~ 1.2 °/点** 为正常；
- 太小（比如 0.05）或太大（比如 3）说明**角度标度或方向有问题**，
  这时画出来的点云形状可能对、尺寸全错，别信障碍识别结果。

### 6.7 点云镜像/对不上怎么排查

1. 方向（东西对、南北反）→ 切换【角度顺时针】；
2. 整体转了一个角度 → 调雷达 `yaw`（先用 15°/5° 按钮粗调）；
3. 位置整体偏 → 雷达 `x/y` 或车起点 `x/y`；
4. 尺寸差 4 倍 → 协议解析问题（当前驱动已修正，见 [lidar_d6.py](../上位机/lidar_d6.py) 顶部说明）。

## 7. 障碍识别

### 7.1 流程

```
回波点 → 场地内 + 量程过滤 → 按 90mm 距离聚类
       → 对每一堆拟合圆 → 半径和 φ50 对得上 = 圆柱(circle)
       → 点太少拟合不出 = blob（"这里有东西"）
```

### 7.2 参数怎么调

| 现象 | 调哪个 |
|---|---|
| 把噪声当障碍 | 加大 `blob_min_points` / `min_points` |
| 真圆柱被漏掉 | 减小 `min_points` / 加大 `radius_tol_mm` |
| 一个圆柱被拆成两堆 | 加大 `cluster_gap_mm` |
| 两个障碍被合成一个 | 减小 `cluster_gap_mm` |
| 近处地面回波多 | 加大 `scan.range_min_mm` |

### 7.3 整格封锁

勾着【整格封锁】时，障碍所在的 **5×5 整格（450×450）** 全封死——保守但稳。
关掉后只按物体的真实半径 + 车半径膨胀绕行。

**工位所在格不封锁**：工位区（扫码区/原料区/…）所在的那一格如果被雷达影子
占住，封了车就永远到不了工位，所以程序会跳过并提示"XX 是工位格，不封锁"。

### 7.4 局限

- 雷达只扫**一个水平面**（安装高度约 120mm）。比这个面低的东西（纸片、薄垫）
  看不见；悬空的东西（桌沿）可能只看到一部分。
- 黑色/镜面/玻璃物体回波弱，可能漏检。
- 车开走以后再出现的障碍，**必须重新扫描**才会进地图。
- 地图坐标系不变，扫到的人、椅子都当作静态障碍。

## 8. 路径规划

### 8.1 栅格与 A*

- 场地切成 20mm 小格（`grid.cell_mm`），可通行掩码按田字 + 启停区生成。
- 障碍按**车半径**膨胀成禁区，然后在格子上跑 A*。
- 结果是一条世界坐标折线，再压成少量路点。

### 8.2 两种走法

| 选项 | 含义 | 效果 |
|---|---|---|
| 沿格中线（默认开） | 走 5×5 格的中线，4 连通 | 路径只有**直行和 90° 转**，正好对上 `move/turn/goto`；更规整，但绕路 |
| 关掉 | 8 连通 + 拉直 | 路径短、可以斜着走；但 `goto` 位姿控制要同时收敛 x/y/θ |

### 8.3 车半径退让

先按 `robot.radius_mm=170` 膨胀。走不通就依次退到 90%、80% … 50% 再试，
成功时会在规划结果里写"放宽到车半径的 XX% 才通得过"。
如果最小余量小于 20mm，还会追加"（余量仅 XXmm，很勉强）"。

> 退让是为了应对"400 车道放一个 φ50 圆柱"这种能挤过去的情况。
> 看到"放宽到 50%"时请人工判断，别盲目让车跑。

### 8.4 目标不可达

- 目标格本身被封锁 → A* 自动改到**最近的可通行格**，规划结果会提示
  "⚠ XX 本身被封锁，已改到最近的可通行点"。
- 整条路被堵死 → 显示"规划失败：无解：路被完全堵死"，并列出是哪几个整格封锁把路断了。
- 起点被卡住（车压到了膨胀后的禁区）→ 也会就近找一个可走格。

### 8.5 怎么读规划结果

```
规划：odom (+1.351, +0.418) m  [C3]  5 个路点  无圆柱障碍  正常通过
```

- 目标（odom）+ 场地格名；
- 路点数 = 实际下发的 `goto` 条数；
- 余量：路径离障碍最近多少 mm（没有圆柱时显示"无圆柱障碍"）；
- 结论：正常通过 / 放宽到 XX% / 无解。

## 9. 导航

### 9.1 三种定目标的方式

| 方式 | 操作 | 目标精度 |
|---|---|---|
| 点地图 | 鼠标左键点地图 | 勾【吸附格心】时吸到最近的 5×5 格心 |
| 格子号 | 填 `C3` 点【去】 | 格心 |
| odom 坐标 | 填 `目标 odom x, y`（米）点【去】 | 任意点（20mm 栅格） |

### 9.2 点击即导航

- 勾着（默认）：点地图 → 规划 → **立刻下发并开始走**。
- 取消：点地图只规划、画路径，确认后点【▶ 导航到目标】。

### 9.3 路点与航向

- 折线先去重（<15mm 的点）、再去共线点，只保留拐点和终点。
- 每个路点的目标朝向 = **指向下一个路点的方向**；最后一个路点 = 从上一个路点
  指向它的方向（即保持行驶方向到达）。
- 所有路点都换算成里程计系后下发：

```json
[
  {"cmd": "comment", "text": "导航 → C3 odom (+1.351, +0.418) m"},
  {"cmd": "goto", "x_m": -0.014, "y_m": -0.004, "yaw_deg": -27.8},
  ...
]
```

### 9.4 下发前后会发生什么

1. 上位机检查：有 `/odom`、已标定、`/robot_status` 就绪（不是就绪会弹框确认）。
2. 发 `/motion_load`，motion_planner 立刻 `_start()`：把目标初始化为**当前里程计位姿**。
3. planner 置 `/motion_active=True`，手柄让位；每 0.1s 重发一次当前目标位姿
   （防止偶发速度帧把 F407 的位置闭环清掉）。
4. 到位判定：`位置误差 < 2cm` **且** `朝向误差 < 2.9°`（`arrive_tol_xy` /
   `arrive_tol_yaw` 可调）。两者都满足才走下一条。
5. 全部走完 → `/motion_active=False`，手柄恢复。

### 9.5 超时与停止

- 每条 `goto/move/strafe/turn` 有 **20 秒**到位超时（`arrive_timeout_s` 参数）。
  超时后：锁定当前位置 → 停止 → 交还手柄 → 状态显示"超时停止"。
- 典型超时原因：车被顶住/打滑、航向环收敛不了（**注意到位要求位置和朝向同时达标**）、
  目标点在障碍膨胀区里。
- 半路停车：底部【■ 停止（含导航）】，剩余路点不再执行。

### 9.6 手柄互斥

- planner 执行期间以 10Hz 发 `/motion_active=True`，`joy_control` 收到后
  除 **B（失能）** 外全部不理。
- 上位机停止、跑完、或者 GUI/planner 崩溃导致心跳中断 **0.6 秒**，
  `joy_control` 自动恢复手柄控制。
- 所以"手柄没反应"先看是不是上位机还在跑。

## 10. 任务路线

- 路线来自 `field.json` 的 `mission.route`，默认：
  `START → 扫码区 → 原料区 → 粗加工区 → 暂存区 → 原料区 → 粗加工区 → 暂存区 → START`。
- 【规划全程】：逐段 A*，显示 `x/y 段可通 总长 x.xx m 约 xx s`，不通的段会列出原因。
- 【执行全程】：
  1. 任一段不通就拒绝下发（弹框告诉你第几段）；
  2. 车不在任务起点（>150mm）时，先规划一段过去；
  3. 把每段拆成 `goto`，整包下发。**中途任何一条超时/停止，全程作废**。
- 【清空】清掉规划结果，不影响场地和障碍。

## 11. 动作序列

### 11.1 指令表

| `cmd` | 参数 | 说明 | 是否阻塞 |
|---|---|---|---|
| `move` | `dist_m` | 前进/后退（米，负=后退） | 是（等到位） |
| `strafe` | `dist_m` | 横移（米，正=左） | 是 |
| `turn` | `deg` | 原地转（度，正=左转/逆时针） | 是 |
| `goto` | `x_m,y_m,yaw_deg` | **绝对位姿（里程计系）** | 是 |
| `gimbal` | `yaw_deg,lift_deg,extend_deg` | 云台三轴（度） | 否 |
| `gripper` | `deg` | 夹爪 0~180 | 否 |
| `plate` | `deg` | 载物盘 0~180 | 否 |
| `cam` | `deg` | 相机 0~180 | 否 |
| `enable` | `true/false/1/0/开/关` | 使能/失能 | 否 |
| `delay` | `ms` | 原地等待 | 是（按时长） |
| `calibrate` | 无 | 视觉校准占位，当前什么都不做 | 否 |
| `comment` | 任意文本 | 注释，跳过 | 否 |

示例（导出 JSON）：

```json
[
  {"cmd": "comment", "text": "取料流程"},
  {"cmd": "goto", "x_m": 0.4, "y_m": 0.0, "yaw_deg": 0.0},
  {"cmd": "delay", "ms": 500},
  {"cmd": "gimbal", "yaw_deg": 0, "lift_deg": 30, "extend_deg": 120},
  {"cmd": "gripper", "deg": 45}
]
```

### 11.2 编辑方式

- 左侧选指令类型 → 填参数（提示文字会给出格式）→【＋添加】；
- 【上移】【下移】【删除】【清空】；
- 【导入JSON】/【导出JSON】整段读写文件；
- 列表里显示的 `goto` 已经是里程计坐标。

## 12. 状态与错误码

`/robot_status = [state, err, motor_mask]`：

| 字段 | 含义 |
|---|---|
| `state` | `0` 未使能 / `1` 就绪 / `2` 故障 |
| `err` | bit0 树莓派离线、bit1 急停、bit2 电机掉线（十六进制显示） |
| `motor_mask` | 各电机在线位图（十六进制） |

> 当前固件只置 bit0（树莓派离线），bit1/bit2 是预留位，暂时不会亮。

界面右下角示例：`整车: 就绪  错误=0x00  电机=0xFF`。

**`state != 1` 时下发导航会先弹确认框**——车没使能，下发了也不会动。

## 13. 首次上车 / 换场地 checklist

按顺序做，做完再让车跑：

- [ ] 量场地：`field.width/height`、`lane.width_mm`、`lane.ring_mm`、`yellow_blocks.size_mm`
- [ ] 量黄块位置：确认"内边贴车道边"，不对就改 `gap_from_lane_mm`
- [ ] 确认启停区、四个工位的位置和 `approach` 点
- [ ] 确认 `robot_start` = 上电时车的真实场地位姿（位置 + 朝向）
- [ ] 确认雷达安装：装在车上就把 `lidar.x/y/yaw` 设成和 `robot_start` 一样
- [ ] 雷达 `angle_cw` 对不对：扫一圈看黄块/墙是否和地图重合
- [ ] 点【保存场地参数】
- [ ] 用模拟雷达走一遍完整流程（连接 → 扫描 → 识别 → 点目标 → 导航）
- [ ] 真雷达：扫描 → 看帧体检是否 0.3~1.2°/点 → 看障碍位置和实物是否一致
- [ ] 车摆回起点 → 标定 → 点最近的一个格心，低速验证一段
- [ ] 验证超时：故意给一个 2m 外的点，看 20s 后是否安全停止

## 14. 故障排查

| 现象 | 先看/先做 |
|---|---|
| `no display name and no $DISPLAY` | 在桌面/VNC 里跑；或 `ssh -X`；`run_gui.sh` 已处理 DISPLAY/XAUTHORITY |
| 跟 `Authorization required` | 有别的终端设了错误的 `XAUTHORITY`；`unset XAUTHORITY` 再跑脚本 |
| 串口列表是"(没插串口)" | USB 没插好；`ls /dev/ttyUSB*`；重新插拔后点【刷新】 |
| `Permission denied` 打开串口 | `sudo usermod -aG dialout $USER`，重新登录 |
| 点云整体镜像 | 切换【角度顺时针】 |
| 点云相对地图转了一个角度 | 调 `lidar.yaw_deg`，用 15°/5° 按钮 |
| 帧体检数值离谱 | 驱动/波特率不对；确认不是 X3 PRO 的口 |
| 障碍列表里出现"人" | 扫描时清场，重扫 |
| 规划"无解：路被完全堵死" | 看红色整格；障碍确实堵死就移开或取消【整格封锁】 |
| 规划成功但车不动 | 状态机是否在跑；整车是否 `就绪`；手柄是否还在占权（先点停止） |
| 点导航没弹错、状态栏"状态机"一直是 `—` | motion_planner 没起来或已经崩了（`ros2 node list` 里没有 `/motion_planner`）；重启 `run_car.sh`，终端要出现"状态机就绪，等待 /motion_load" |
| 车走一半停了，状态"超时停止" | 20s 没同时满足位置 2cm + 朝向 2.9°；看是否转向卡住/打滑，可调 `arrive_timeout_s` |
| 地图上车的位置越走越偏 | `robot_start` 写错、标定错、轮子打滑、IMU 漂移；先回到起点重新标定验证 |
| 位姿显示"⚠ 未标定车起点" | 车不在起点附近；摆回起点点【标定里程计】 |
| 悬停显示"odom 未标定" | 同上；没标定时不能导航 |
| 导航按钮没反应/弹窗"还没有可执行的路径" | 先点地图或用【去】生成路径 |
| 雷达扫不到矮/黑色物体 | 雷达只扫一个水平面，属正常局限；换装高度或换障碍物测试 |

- F407 上电不归零 yaw，导致每次上电都要标定一次（见 §4.5）；
- 雷达只有一个水平面，低矮障碍会漏；
- `scan.min_intensity`、`cylinder.height_mm`、`lidar.height_mm` 目前只是记录字段。
