# 上位机 + 状态机 使用指南

这套东西解决的问题：**赛前没有场地，也能把"走多少、转多少、到哪干什么"的整套动作逻辑调好，
调完直接打包给 `motion_planner` 在场上自动跑。**

## 一、整体架构（四层）

```
┌─────────────┐  ROS2(WiFi)   ┌──────────────────┐  串口    ┌──────────┐
│ 上位机(笔记本) │ ──────────▶ │ motion_planner(状态机)│ ─────▶ │ F407     │
│ 编辑/测试/看轨迹│ ◀────────── │ f407_bridge(桥)      │ ◀───── │ 底盘+云台 │
└─────────────┘              └──────────────────┘         └──────────┘
   编辑动作序列         →      逐条执行、判断到位      →     位置闭环/航向闭环
```

- **上位机**：笔记本上的 GUI，编辑动作序列、下发测试、实时画里程计轨迹。
- **motion_planner**：状态机，把"相对指令"（前进0.5米）累计成"绝对位姿"，发给 F407，等到位再执行下一条。
- **f407_bridge**：串口桥，话题 ↔ 协议字节互转。
- **F407**：底盘 4 电机编码器 + 陀螺仪做**位置闭环 + 航向闭环**（这是走准的根本）。

关键设计：**上位机里编辑的指令序列 = 场上 motion_planner 执行的同一份 JSON**。
测什么，场上就跑什么。

## 三、使用步骤

### 第 1 步：重新烧录 F407
把 `UniversalCar/` 用 Keil 重新编译烧到板子上（改了 `PiComm.c/h`、`ChassisTask.c`、`ReceiveTask.c`）。
> 云台三轴电机还没装，`RobotConfig.h` 里 `GIMBAL_MOTOR_INSTALLED` 保持 0 即可，
> 云台指令现在会发出去但 F407 不执行（装了再改回 1）。

### 第 2 步：树莓派重新 build
```bash
cd ~/GongChuang/树莓派/ros2_ws
colcon build --symlink-install
source install/setup.bash
ros2 launch car_bringup system.launch.py
```
（`--symlink-install` 让改 Python 不用反复 build，直接重启节点即可。）

### 第 3 步：笔记本跑上位机
前提：笔记本装了 ROS2（和树莓派同版本），并 `export ROS_DOMAIN_ID=0`（两边一致）保证 DDS 互通。
```bash
cd 树莓派/上位机
python3 motion_gui.py
```
连上后界面上会显示里程计、状态机进度、整车状态。

### 第 4 步：编辑 + 测试 + 导出
1. 在左侧选指令类型、填参数、点「＋添加」，组出一串动作。
2. 点「▶ 执行整段」发给树莓派跑；或选中一条点「▶ 执行选中一条」单步试。
3. 右侧画布实时画出轨迹：**正方形能闭合 = 位置闭环准**，越不闭合说明漂移越大（去 F407 的 `ChassisTask.c` 调 `CHASSIS_RETURN_KP/KI` 和 `CHASSIS_HEADING_KP`）。
4. 调好点「导出 JSON」存文件，赛场上让 `motion_planner` 加载它（见下）。

### 第 5 步：场上自动跑
把导出的 JSON 放到树莓派上，用启动参数指定：
```bash
ros2 run motion_planner motion_planner_node --ros-args -p sequence_file:=/path/to/sequence.json
```
或直接在 `system.launch.py` 里给 motion_planner 节点加这个参数。

## 四、指令格式速查

| 指令 | 写法 | 说明 |
|---|---|---|
| move | `{"cmd":"move","dist_m":0.5}` | 前进(负=后退)，米 |
| strafe | `{"cmd":"strafe","dist_m":0.3}` | 横移(正=左)，米 |
| turn | `{"cmd":"turn","deg":90}` | 原地转(正=左转/逆时针，负=右转)，度 |
| gimbal | `{"cmd":"gimbal","yaw_deg":-30,"lift_deg":50}` | 云台三轴绝对角，可缺省，不阻塞 |
| gimbal_yaw | `{"cmd":"gimbal_yaw","delta_deg":5}` | yaw 相对微调，阻塞到位 |
| gimbal_lift | `{"cmd":"gimbal_lift","delta_deg":-20}` | lift 相对微调，阻塞到位 |
| gimbal_ext | `{"cmd":"gimbal_ext","delta_deg":30}` | extend 相对微调，阻塞到位 |
| gripper | `{"cmd":"gripper","deg":45}` | 夹爪舵机 0~180 |
| plate | `{"cmd":"plate","deg":90}` | 载物盘舵机 |
| cam | `{"cmd":"cam","deg":0}` | 相机舵机 |
| enable | `{"cmd":"enable","en":true}` | 使能/失能电机 |
| delay | `{"cmd":"delay","ms":1000}` | 原地等待毫秒 |
| calibrate | `{"cmd":"calibrate","x_m":-2.169,"y_m":1.061}` | 圆环工位视觉矫正（见第六节），阻塞 |
| color_pick | `{"cmd":"color_pick","color":1}` | 云台跟随该颜色物料到画面中心，**阻塞**到对中（1~6，也可写 `$b1c1$` 占位符）。只跟随不抓取 |
| color_pick open | `{"cmd":"color_pick","color":"open"}` | 提前把视觉进程和摄像头点起来，**不阻塞**。车还没到工位时先跑这一条 |
| color_pick close | `{"cmd":"color_pick","color":"close"}` | 关闭常驻视觉进程，释放摄像头 |
| comment | `{"cmd":"comment","text":"..."}` | 注释，不执行 |

**坐标约定**：车正前方 = +x，左侧 = +y，逆时针 = 正。和 F407 里程计/陀螺仪一致。

## 五、注意事项

1. **动之前必须先使能**：序列第一句最好放 `{"cmd":"enable","en":true}`（或在上位机点「使能」）。
2. **turn 的正负**：正 = 左转（逆时针），负 = 右转。别搞反（和 JY901S 陀螺仪一致）。
3. **到位判定**：位置 2cm + 朝向 3° 内算"到了"，可在 `motion_planner` 的 `arrive_tol_xy/arrive_tol_yaw` 参数调。
   `goto/move/strafe` 是**先平移到位、停稳后再原地转向**（行进段锁住出发朝向，
   不让车边走边转，避免麦轮打滑把里程计带漂）；停稳时间由 `turn_settle_s` 调（默认 0.3s）。
4. **串口没数据**：如果上位机一直显示"未收到里程计"，先确认 F407 已烧新固件、串口接线对、`f407_bridge` 在跑。
5. **雷达目前没接进状态机**：障碍绕行（检测到障碍换条路）是后续要加的钩子，现在 `motion_planner` 不订阅 `/obstacles`。
6. **`color_pick` 是常驻进程**：`open` 之后视觉程序一直开着摄像头，直到 `close`、序列被叫停、或重新加载序列。这期间 `calibrate`（ring_fix 要开摄像头）会抢不到 `/dev/video0`，两种视觉别同时跑。抓完最后一种颜色记得补一条 `color_pick close`。

## 六、圆环工位视觉矫正（`calibrate` 指令）

比赛全程里程计会累计漂移，到工位时可能已经偏了几厘米。`calibrate` 用**存放物料的三圆环**
当"视觉地标"把漂移一次清掉：

1. 车先用普通 `goto` 开到圆环工位附近（粗定位，米级即可）；
2. 执行到 `{"cmd":"calibrate","x_m":-2.169,"y_m":1.061}` 时，motion_planner 把圆环坐标发给
   `ring_fix` 节点；
3. ring_fix 打开摄像头（触发时才开，**平时不占用摄像头**），逐帧跑
   `vision/ring_station_detector.py` 识别三个圆环，按标定的纠偏矩阵把偏差裁成小步
   （≤40mm/≤4°）发 `/cmd_pose`，**把中间环对到标定基准（参考图像）**；
4. 连续 3 帧纠偏量小于门槛（默认 4mm / 1.5°）即认为对准——此时车体相对中间环的位置是
   固定值，`ring_fix` 发 `/set_odom` 把里程计锚定到"圆环坐标 + 对准偏移"；
5. f407_bridge 从这时起在 `/odom` 上报时加偏移、在 `/cmd_pose` 下发时减偏移，
   **ROS 侧所有位姿自动活在修正坐标系里**，F407 固件不用改；
6. 上位机收到 `/odom_shift` 会同步平移自己的"车起点"锚点，地图不跳变。

**需要的一次性标定**（ring_fix 节点参数）：

- `align_offset_x_m` / `align_offset_y_m`：对准后**车体里程计坐标 − 圆环里程计坐标**。
  默认 0 = 认为"对准位置就是圆环坐标"。标定方法：手动对准后读 `/odom`，减去圆环坐标填入。
- `align_yaw_deg`：对准后车体的航向（度）。留空 = 只修位置不修航向。

**前提**：

- `vision/config/ring_station_detector.json` 的参考圆心、`chassis_image_to_motion`
  纠偏矩阵必须已标定（这是"往哪动"的依据）；
- 触发前云台/相机已摆到参考姿态，且 `vision/main.py` 没占用摄像头；
- 识别不到 / 超时（默认 45s）→ 该条跳过、里程计不重置，任务继续。
- **矫正全程树莓派桌面会弹出实时画面**（ring_fix 窗口）：蓝十字 = 标定参考环心，
  绿/黄椭圆 = 当前识别到的圆环，顶部显示纠偏量/稳定帧/剩余时间——用来确认
  云台相机是否摆到参考姿态、有没有看到三个环。纯 SSH 无桌面时自动关闭预览，
  不影响矫正；`show_preview:=false` 可禁用。

> ⚠ **给 ring_fix 节点 build 一次**：`colcon build --symlink-install --packages-select ring_fix`
