## 2. comm/pi_comm.py

全项目最关键的单个文件：它定义了与 F407 通信的字节级协议。改了它，必须同步改 F407 侧的
`UniversalCar/ExHardware/PiComm.c`。

### 2.1 文件头 docstring（L1–L29）

```python
#!/usr/bin/env python3          # L1：可直接 `./pi_comm.py` 执行
"""树莓派 <-> F407 通信（PiComm 协议，USART6，115200 8N1）。..."""
```

- `L1` shebang：让脚本无需显式 `python3` 前缀即可执行；
- `L2–L29` 是协议自述（帧格式、命令表、遥测表），写在这里是为了让「协议」和「实现」在同一个文件里，
  任何人打开文件就能核对协议，不必再翻 F407 源码。

帧格式（L6–L13）：

```
AA 55 | LEN | SEQ | CMD | DATA | CRC16(低字节在前)
```

- `AA 55`：帧头（SOF），两个字节，降低误判概率；
- `LEN` = `CMD(1) + DATA(N) + CRC(2)` = `3 + N`；
- `SEQ`：发送序号，每帧 +1，0~255 回绕。**只用于观测，不参与协议校验**；
- `CRC16-MODBUS`：覆盖 `LEN + SEQ + CMD + DATA`，即从 `LEN` 字节开始，共 `3+N` 字节。

### 2.2 导入（L31–L40）

```python
from __future__ import annotations   # L31
import struct                          # L33
import time                            # L34
from typing import Callable, Optional  # L35

try:                                   # L37
    import serial
except ImportError:                    # L39
    serial = None                      # L40：没装 pyserial 也能用编解码部分
```

- `L31`：PEP 563，让类型注解（如 `-> tuple[float, float, float]`）延迟求值，老版本 Python 也能写新式注解；
- `L33` `struct`：用来做**大端/小端字节打包**，这是二进制协议的核心；
- `L34` `time`：提供 `time.monotonic()` 时钟（不受系统时间跳变影响，适合做重连计时）；
- `L37–L40`：`pyserial` 是可选依赖。这样 `pi_comm.py` 的**纯编解码函数**可以在没有串口的环境（比如
  编译、单测、甚至 F407 侧做一致性测试）里直接 import，只有真正要开串口时才需要 pyserial。

### 2.3 协议常量（L43–L70）

```python
CMD_VEL = 0x01        # L44 速度
CMD_GIMBAL = 0x02     # L45 云台目标
CMD_HOME = 0x03       # L46 云台回零
CMD_GRIPPER = 0x04    # L47 夹爪舵机
CMD_PLATE = 0x05      # L48 托盘舵机
CMD_CAM = 0x06        # L49 相机舵机
CMD_ENABLE = 0x07     # L50 使能/失能
CMD_ESTOP = 0x08      # L51 急停
CMD_HEARTBEAT = 0x10  # L52 心跳

RPT_ODOM = 0x81       # L55 遥测：里程计
RPT_STATUS = 0x83     # L56 遥测：整车状态

SOF1 = 0xAA           # L58
SOF2 = 0x55           # L59
MAX_FRAME = 64        # L60 与 F407 侧 PI_RX_BUF_SIZE 一致

ERR_ESTOP      = 1 << 0  # L63 急停错误位
ERR_PI_OFFLINE = 1 << 1  # L64 树莓派离线位
ERR_MOTOR_LOST = 1 << 2  # L65 电机丢失位

ROBOT_DISABLED = 0    # L68
ROBOT_READY    = 1    # L69
ROBOT_FAULT    = 2    # L70
```

- 命令码 `0x01~0x10` 是「树莓派 → F407」方向，遥测码 `0x81/0x83` 是「F407 → 树莓派」方向。
  **方向用最高位区分**（0x80 以上是回传），这是很多二进制协议的惯例；
- `MAX_FRAME = 64` 必须和 F407 接收缓冲区大小一致，否则可能帧被截断；
- `L62–L70` 是**状态机/错误位**的镜像定义。注意：这些值真正生效在 F407 侧
  （`ReceiveTask.c`），这里只是「照抄一份」让树莓派端解析 `0x83` 时能读懂含义，
  两边必须保持同步。

### 2.4 自定义异常（L73–L74）

```python
class PiCommError(ValueError):
    """帧编解码或串口配置错误。"""
```

继承 `ValueError`：表示「参数/数据值不合法」（如角度越界、帧过长）。单独一个异常类，
方便调用方 `except PiCommError` 精确捕获，而不误吞其它错误。

### 2.5 CRC16-MODBUS（L77–L84）

```python
def crc16_modbus(data: bytes) -> int:
    crc = 0xFFFF                          # L79 初值 0xFFFF
    for byte in data:                     # L80 逐字节
        crc ^= byte                       # L81 字节先异或进 CRC 低 8 位
        for _ in range(8):                # L82 每个字节处理 8 次
            crc = (crc >> 1) ^ 0xA001 if (crc & 1) else crc >> 1  # L83
    return crc & 0xFFFF                   # L84 只保留 16 位
```

- 这是标准的 **CRC16-MODBUS**（多项式 `0xA001`，初值 `0xFFFF`）。`0xA001` 是「反射多项式」，
  所以算法是「右移」而不是常见的「左移」；
- `L83` 逐位：如果最低位是 1，右移后还要异或 `0xA001`；否则只右移；
- 校验向量：`crc16_modbus(b"123456789")` 应等于 `0x4B37`（代码已通过该自检）。

> 为什么必须用这个 CRC？因为 F407 侧 `PiComm.c` 用同一算法，接收端靠它判断帧是否完整无错。
> 算法、初值、覆盖范围三者的任何一个对不上，帧就会被 F407 丢弃。

### 2.6 组帧 build_frame（L87–L105）

```python
def build_frame(cmd: int, data: bytes = b"", seq: int = 0) -> bytes:
    if not 0 <= cmd <= 0xFF:              # L89 功能码合法性
        raise PiCommError(f"功能码越界：{cmd}")
    n = len(data)                          # L91
    if 3 + n > MAX_FRAME:                 # L92 帧长上限
        raise PiCommError(f"帧过长：{3 + n} > {MAX_FRAME}")

    frame = bytearray()                    # L95 可变字节数组
    frame.append(SOF1)                     # L96 AA
    frame.append(SOF2)                     # L97 55
    frame.append(3 + n)                    # L98 LEN = CMD + DATA + CRC
    frame.append(seq & 0xFF)               # L99 SEQ
    frame.append(cmd)                      # L100 CMD
    frame.extend(data)                     # L101 DATA
    crc = crc16_modbus(bytes(frame[2:]))   # L102 覆盖 LEN+SEQ+CMD+DATA
    frame.append(crc & 0xFF)               # L103 CRC 低字节在前
    frame.append((crc >> 8) & 0xFF)        # L104 CRC 高字节在后
    return bytes(frame)                    # L105
```

- `L98`：`3 + n` 即 `CMD(1) + DATA(n) + CRC(2)`，这是帧里唯一带长度信息的字段，接收端靠它知道要收多少字节；
- `L102`：`frame[2:]` 是「LEN 及之后、还没加 CRC 之前」的所有字节 = `LEN+SEQ+CMD+DATA`，
  正好是协议规定的 CRC 覆盖范围；
- `L103–L104`：CRC 按**小端**（低字节在前）放入帧尾。这必须和 F407 接收端
  `crc = (hi << 8) | lo` 的读取顺序一致。

### 2.7 命令数据编码（L108–L138）

```python
def encode_vel(vx_m_s, vy_m_s, wz_rad_s):          # L109 速度
    vx = int(round(vx_m_s * 1000.0))               # L111 m/s -> mm/s
    vy = int(round(vy_m_s * 1000.0))
    wz = int(round(wz_rad_s * 1000.0))             # L113 rad/s -> mrad/s
    for name, val in (("vx", vx), ("vy", vy), ("wz", wz)):
        if not -32768 <= val <= 32767:             # L115 int16 范围检查
            raise PiCommError(f"{name} 超出 int16：{val}")
    return struct.pack(">hhh", vx, vy, wz)         # L117 大端 int16×3
```

- `L111/L113`：树莓派内部用 SI 单位（m/s、rad/s），协议传输用整数（mm/s、mrad/s）。
  **单位换算放在编码层**，上层调用者永远用 SI，不用记协议细节；
- `L115`：`int16` 取值范围 −32768~32767。越界说明调用方给了不合理速度，直接抛错而不是静默溢出；
- `L117`：`>` 表示**大端**（高位字节在前）。F407 侧按 `d[0]<<8 | d[1]` 解析，必须大端对齐。

```python
def encode_gimbal(axis, deg):        # L120 云台目标
    return struct.pack(">Bi", axis, int(round(deg * 100.0)))
```

- 云台角度用 `deg×100` 存成 `int32`，保留 0.01° 精度；`B`（u8）是轴编号，`i` 是 int32。

```python
def encode_servo(pos_deg):           # L131 舵机 0~180°
    if not 0.0 <= pos_deg <= 180.0:
        raise PiCommError(...)
    return bytes([int(round(pos_deg))])
```

- 舵机角度只传 1 字节（0~180 刚好塞进 u8），精度 1° 对舵机足够。

```python
def encode_enable(en, mask=0x7F):    # L137
    return bytes([1 if en else 0, mask & 0x7F])
```

- `mask` 的 bit0~bit6 对应电机 1~7，`0x7F` = 全部 7 个电机。

### 2.8 遥测解析（L141–L154）

```python
def parse_odom(data):                # L142 0x81 帧
    if len(data) != 10:
        raise PiCommError(...)       # L144 长度校验
    x_mm, y_mm, theta_mrad = struct.unpack(">iih", data)  # L146
    return x_mm / 1000.0, y_mm / 1000.0, theta_mrad / 1000.0  # L147 -> m, m, rad
```

- `>iih` = 大端 int32 + int32 + int16，对应协议 `x(int32) y(int32) theta(int16)`；
- `L147` 又把整数单位换回 SI（m、rad），与 `encode_vel` 反向对称。

```python
def parse_status(data):              # L150 0x83 帧
```

### 2.9 串口链路类 PiCommLink（L157–L314）

这个类封装了「非阻塞收发 + 自动重连 + 坏帧重同步」，供 `f407_bridge` 使用。

#### 构造（L163–L182）

```python
def __init__(self, device="/dev/serial0", baudrate=115200,
             reconnect_interval_s=1.0, serial_factory=..., clock=time.monotonic):
```

- `serial_factory` 默认就是 `serial.Serial`，抽出来是为了**单测时能注入假串口**；
- `clock` 默认 `time.monotonic`，同样可注入假时钟；
- `self._rx = bytearray()`：接收缓冲，存放「还没凑成完整帧」的字节；
- `self._seq = 0`：发送序号；`self._next_reconnect_s`：下次允许重连的时刻。

#### connected 属性（L185–L187）

```python
return bool(self._port is not None and getattr(self._port, "is_open", True))
```

`is_open` 在个别 pyserial 版本可能没有，用 `getattr` 兜底。

#### _disconnect（L189–L198）

关端口、清接收缓冲、**把下次重连时间推迟 1 秒**、记录错误。所有「写失败/读失败」都汇到这里。

#### _ensure_connected（L200–L216）

```python
if self.connected: return True            # 已连，直接过
if self._clock() < self._next_reconnect_s: return False  # 还没到重连时间，不狂试
try:
    self._port = self._serial_factory(port=..., baudrate=..., timeout=0, write_timeout=0)
except Exception as error:
    self._disconnect(str(error)); return False
```

- `timeout=0` / `write_timeout=0`：**非阻塞**读写，绝不卡住 ROS2 节点的主循环；
- 每次失败后隔 1 秒再试（`reconnect_interval_s`），避免串口设备插拔瞬间疯狂报错。

#### _send（L219–L233）

```python
frame = build_frame(cmd, data, self._seq)
written = self._port.write(frame)
if written != len(frame):
    raise serial.SerialTimeoutException(...)   # 没写完 = 异常
...
self._seq = (self._seq + 1) & 0xFF             # 序号 +1，0~255 回绕
```

`& 0xFF` 让序号在 255 之后回到 0。

#### send_* 系列（L235–L260）

每个都是 `self._send(CMD_xxx, encode_xxx(...))` 的薄封装，给上层一个**语义化**接口，
上层只写 `link.send_vel(0.1, 0, 0)` 而不用记 `0x01` 这种魔数。

#### poll（L263–L305）—— 接收核心

```python
available = self._port.in_waiting          # L268 当前积压多少字节
data = self._port.read(available)          # L271 一次性读走
self._rx.extend(data)                       # L276 追加到缓冲
```

然后是一个「从缓冲里切帧」的循环：

```python
idx = self._rx.find(b"\xaa\x55")           # L281 找帧头
if idx < 0:
    # L284：没找到帧头——但末尾可能残留半个 0xAA，只保留它，其余全丢
    if self._rx and self._rx[-1] == SOF1:
        del self._rx[:-1]
    else:
        self._rx.clear()
    break
if idx > 0:
    del self._rx[:idx]                     # L290 丢掉帧头前的杂散字节
if len(self._rx) < 4: break                # L291 连 LEN 都没收全，继续等
length = self._rx[2]                       # L293 读 LEN
total = length + 4                         # L294 整帧长 = SOF(2)+LEN+SEQ+LEN字节
if length + 3 > MAX_FRAME:
    del self._rx[0]; continue              # L296 异常 LEN，丢 1 字节重同步
if len(self._rx) < total: break            # L298 还没收满整帧
candidate = bytes(self._rx[:total])        # L300 取出一整帧
crc = (candidate[-1] << 8) | candidate[-2] # L301 帧尾两个字节拼出 CRC
if crc16_modbus(candidate[2:-2]) == crc:   # L302 校验
    frames.append((candidate[4], candidate[5:-2]))  # L303 收下 (cmd, data)
del self._rx[:total]                       # L304 从缓冲移除这一帧
```

要点：

- **缓冲 + 切帧**：串口是流式字节流，一次 `read` 可能返回半帧或一帧半，所以必须先攒进缓冲再切；
- **重同步**：帧头不对就丢杂散字节；LEN 异常（`length + 3 > MAX_FRAME`）说明已失步，丢 1 字节重找；
- **CRC 校验**：`candidate[2:-2]` 是「去掉 SOF 和 CRC」的部分，和发送端 `frame[2:]` 完全对应；
- 坏帧（CRC 不匹配）会被**静默丢弃**——串口偶发误码不该让上层感知。

#### close（L307–L314）

关端口、清缓冲，供节点销毁时释放。

## 4. ROS2 工作区与 colcon 结构

`ros2_ws/` 是一个标准 **colcon 工作区**：

```
ros2_ws/
├── src/              # 所有源码包（我们手写的 + clone 的 ydlidar_ros2_driver）
├── build/            # colcon 构建中间产物（构建后生成，可删）
├── install/          # 构建结果（bringup.sh 里 source 的就是这里的 setup.bash）
└── log/              # 构建日志
```

每个包都有一个 `package.xml`（描述包身份和依赖）和 `setup.py`（Python 包安装规则）。
`package.xml` 顶部 `format="3"` 是当前 ROS2 的包格式版本。

**为什么源码在 `src/` 但运行时在 `install/`？**
colcon 会把每个包「安装」到 `install/<包名>/`，可执行程序（`entry_points` 里的
`console_scripts`）会出现在 `install/<包名>/lib/<包名>/`。所以必须先
`source install/setup.bash`，`ros2 run` 才能找到这些命令。

下面每个功能包，我都会先讲「壳」（package.xml / setup.py / resource / __init__.py），
再讲真正的节点代码。

## 5. lidar_bringup 包

「bringup」= 把某个硬件（这里指激光雷达）「带起来」的启动包。它**不含任何节点代码**，
只有参数和 launch 文件，负责配置并拉起 `ydlidar_ros2_driver` 这个第三方驱动节点。

### 5.1 package.xml

```xml
<package format="3">                  <!-- ROS2 包格式版本 -->
  <name>lidar_bringup</name>          <!-- 包名，必须和目录名一致 -->
  <version>0.1.0</version>
  <description>...</description>
  <maintainer email="...">kblue</maintainer>
  <license>MIT</license>
  <buildtool_depend>ament_python</buildtool_depend>  <!-- 用 ament_python 构建 -->
  <export>
    <build_type>ament_python</build_type>            <!-- 同上，旧写法兼容 -->
  </export>
```

```python
class ObstacleDetectNode(Node):              # L16 继承 Node
    def __init__(self):
        super().__init__('obstacle_detect')  # L18 节点名
        self.declare_parameter('half_deg', 60.0)     # L19 扇区半角，可在命令行覆盖
        self.declare_parameter('clear_range', 3.0)   # L20 无测量时的"开阔"值

        self.clear_range = self.get_parameter('clear_range').value # L22
```

- `L19–L22`：`declare_parameter` 声明一个带默认值的参数，`get_parameter().value` 读出来。

- `L24`：发布器，话题 `/obstacles`，消息类型 `Float32MultiArray`，**QoS 队列深度 10**

- `L25`：订阅器，`/scan` → 回调 `self._cb`，深度 10。

```python
def _cb(self, scan: LaserScan):              # L27 每来一帧雷达数据触发一次
    front = self._sector(scan, 0.0)          # L28 正前方 0°
    left  = self._sector(scan, 90.0)         # L29 左侧 90°
    right = self._sector(scan, 270.0)        # L30 右侧 270°（-90°）
    back  = self._sector(scan, 180.0)        # L31 正后方 180°
    self._pub.publish(Float32MultiArray(data=[front, left, right, back]))  # L32
```

- 四个方向正好覆盖车体四周，`right` 用 `270°` 而不用 `-90°`，是为了和下面的取模逻辑配合；
- `L32`：构造消息并发布。`data=[...]` 是四个 float，按顺序就是「前、左、右、后」。

```python
def _sector(self, scan, center_deg):         # L34 求某扇区内最近距离
    best = self.clear_range                  # L35 初值=开阔值（找不到就返回它）
    for i, r in enumerate(scan.ranges):      # L36 遍历每个角度的距离
        ang_deg = math.degrees(scan.angle_min + i * scan.angle_increment) % 360.0  # L37
        diff = (ang_deg - center_deg + 180.0) % 360.0 - 180.0   # L38 最短角度差
        if abs(diff) <= self.half_deg and math.isfinite(r) and r >= scan.range_min:
            best = min(best, float(r))       # L40 取更近的
    return best
```

- `L37`：由「第 i 个点」算角度：`angle_min + i * angle_increment`，再 `% 360` 归一化到 0~360；
- `L38`：**带环绕的最短角度差**。`(a - b + 180) % 360 - 180` 这个公式能把角度差映射到 −180~+180，
  正确处理了 0°/359° 这种跨 0 的情况。有了它，扇区中心用 0/90/180/270 都不会在「绕一圈」处出错；
- `L39` 三个过滤条件：在扇区内（`abs(diff) <= half_deg`）、距离是有限值（排除 `inf`/`nan`）、
  不小于最小量程（排除 0 或负值的无效点）。激光雷达对「没打到东西」常用 `inf` 表示，
  不滤掉的话 `min` 会被它污染；
- `L40`：扇区内取最近的那一个点——障碍检测关心的是「最近的危险距离」。

```python

```

- `L37–L43` 是三档「前向」策略：停 / 减速 / 全速。`L41` 的 `ratio` 把「离停车的距离」线性映射到
  0~1，越近速度越低，是简单的比例逼近；
- `L39`：停车时朝**更开阔的一侧**原地转（哪边障碍远就往哪边转），这是最基本的脱困动作；
- `L46–L50`：侧面让行用 `linear.y`（麦克纳姆轮可以横向移动，所以直接横移让开）。
  这是**浅规则占位**，真正的避障/任务规划后面替换。

`main()` 与 obstacle_detect 完全相同，不再赘述。

> ⚠️ 这个节点是**明确标注的占位实现**。它只解决「别撞墙」，不做循迹、取放、码放。
> 等视觉结果接入 ROS2 后，应替换成真正的任务规划节点。

## 9. scripts/setup.sh

环境准备脚本，`set -euo pipefail` 开头：任何命令失败立即退出（`-e`）、
引用未定义变量报错（`-u`）、管道里任一环节失败算失败（`-o pipefail`），避免脚本「带病跑完」。

```bash
REPO_ROOT="$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)"   # 定位到 树莓派/ 目录
ROS_DISTRO="${ROS_DISTRO:-lyrical}"   # 允许环境变量覆盖，默认 lyrical
```

- `${BASH_SOURCE[0]}` 是脚本自身路径，`dirname` 去掉文件名得 `scripts/`，`..` 回到 `树莓派/`，
  这样**不管从哪个目录执行脚本都能正确定位仓库根**。

```bash
echo "==> 1/6 系统依赖"
sudo apt-get update
sudo apt-get install -y python3-pip python3-serial python3-numpy python3-opencv \
    git curl wget cmake python3-colcon-common-extensions
sudo usermod -aG dialout "$USER" || true
```

- `python3-serial`：pyserial（pi_comm 需要）；`python3-opencv`：视觉需要；
  `python3-colcon-common-extensions`：colcon 构建工具；
- `usermod -aG dialout`：把当前用户加进 `dialout` 组（串口设备属主组），以后访问串口不用 sudo；
  `|| true` 让这步即使失败也不中断脚本（比如组已存在）。

```bash
echo "==> 2/6 ROS2 ${ROS_DISTRO}"
if ! dpkg -s "ros-${ROS_DISTRO}-desktop" >/dev/null 2>&1; then
    echo "  [!] 未检测到 ROS2 ... 请先安装 ..."
    exit 1
fi
```

- 用 `dpkg -s` 检测 ROS2 桌面包是否已装；没装就**打印安装指引并退出**，而不是替用户装
  （ROS2 安装步骤多、需要用户确认，脚本里硬装容易出错）。

```bash
echo "==> 3/6 串口"
CONFIG_TXT=/boot/firmware/config.txt
[ -f "$CONFIG_TXT" ] || CONFIG_TXT=/boot/config.txt
grep -q '^enable_uart=1' "$CONFIG_TXT" || echo 'enable_uart=1' | sudo tee -a "$CONFIG_TXT"
grep -q '^dtoverlay=disable-bt' "$CONFIG_TXT" || echo 'dtoverlay=disable-bt' | sudo tee -a "$CONFIG_TXT"
```

- `CONFIG_TXT` 兼容两种路径（Ubuntu 新旧版本 config.txt 位置不同）；
- `grep -q ... || echo ... | tee -a`：先查「是否已有这行」，没有才追加，**可重复执行不会重复写**。

```bash
echo "==> 4/6 YDLIDAR udev 规则"
sudo bash -c 'cat > /etc/udev/rules.d/ydlidar.rules <<EOF
KERNEL=="ttyUSB*", ATTRS{idVendor}=="10c4", ATTRS{idProduct}=="ea60", MODE:="0666", SYMLINK+="ydlidar"
EOF'
sudo udevadm control --reload-rules && sudo udevadm trigger
```

- 这行规则说：当某个 `ttyUSB*` 设备的 VID/PID 是 `10c4:ea60`（CP2102 串口芯片，X3 PRO 用的），
  就给它建一个固定符号链接 `/dev/ydlidar` 并放开权限；
- `reload-rules` + `trigger`：让新规则立即生效。

```bash
echo "==> 5/6 YDLIDAR ROS2 驱动"
source "/opt/ros/${ROS_DISTRO}/setup.bash"
git clone --recursive https://github.com/YDLIDAR/ydlidar_ros2_driver.git ...
```

- `--recursive`：连 YDLidar-SDK 子模块一起拉，否则编译缺依赖。

```bash
echo "==> 6/6 构建"
cd "$REPO_ROOT/ros2_ws"
colcon build --symlink-install
```

- `--symlink-install`：安装时用**符号链接**指向 `src/` 里的源码，改 Python 代码后不用重新 build
  就能生效（只对 Python/launch/yaml 有效，C++ 仍需重编）。开发期强烈推荐。

结尾 `echo` 打印三行收尾提示（重启、确认 `/dev/ydlidar`、启动）。

## 10. scripts/bringup.sh

```bash
#!/usr/bin/env bash
set -euo pipefail
REPO_ROOT="$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)"
ROS_DISTRO="${ROS_DISTRO:-lyrical}"

source "/opt/ros/${ROS_DISTRO}/setup.bash"        # 1) 加载 ROS2 环境
source "$REPO_ROOT/ros2_ws/install/setup.bash"     # 2) 加载我们工作区的包

exec ros2 launch lidar_bringup system.launch.py    # 3) 启动并"接管"当前进程
```

- `source .../setup.bash` 是 ROS2 的老规矩：把 `ros2` 命令、我们的包、依赖都加进环境变量；
- `exec`：用 launch 进程**替换**当前 shell 进程，这样 Ctrl-C 的信号能直接送到 launch，
  干净地停掉所有节点（不留孤儿 shell）。
