按塔克那套 cspc 上位机的思路重做的，但目标换成本比赛：

## 二、怎么跑

```bash
cd map_app

python selftest.py     # 只看算法结果，出 preview.png，不需要任何第三方库（要 PIL）
python app.py          # 打开界面
```

界面上默认勾着 **「用模拟雷达」**——没插雷达也能把整套流程点一遍。

接真雷达时：
1. 取消勾选「用模拟雷达」，选串口和波特率（D6 出厂 **230400**）；
2. 点【连接并开始】；
3. 点【① 扫描建图】→ 扫满配置的圈数后自动冻结并识别；
4. 左键点地图任意位置 = 设目标点，自动规划。

依赖：`tkinter`（Python 自带）、`pyserial`（只有接真雷达才需要）。`selftest.py` 和截图脚本要 `Pillow`。

### 接真雷达时卡住怎么办

**先跑串口探针**，不看界面，2 秒就知道通不通：

```bash
python port_probe.py            # 自动找 CH340/CP210x 那个口
python port_probe.py COM22      # 指定口
python port_probe.py COM22 115200
```

输出 `✅ 通了。距离范围 620 ~ 5200 mm` 就说明驱动、波特率、接线都对。
输出 `❌ 一个数据帧都没收到` 它会直接列出排查顺序。

**常见坑（已处理）**

| 现象 | 原因 | 现在怎么处理 |
|---|---|---|
| 状态栏写"模拟雷达已启动（无硬件）" | 「用模拟雷达」还勾着 | 现在**检测到串口就默认真机模式**，一个口都没有才默认模拟 |
| 下拉框里是假的 COM3/COM4/COM5 | 没装 pyserial 时的旧兜底 | 现在直接显示 `(未装 pyserial)`，不再伪造 |
| 不知道哪个口是雷达 | —— | 下拉框显示型号，且**优先自动选 CH340/CP210x/FTDI** |
| 打不开串口 | JCom / 塔克上位机还占着 | 先关掉那个程序 |

## 三、为什么地图是"参数画的"而不是雷达扫出来的

二维雷达只看得见**立在扫描平面里的东西**。地面上的灰色车道、淡黄色方块是平的，
雷达一点回波都没有。所以：

- **地图 = 参数模型**（`field.json` 或界面上直接改）→ 这也是"尺寸会变"的唯一正确解法；
- **雷达 = 在模型上标障碍物**。

现场只需要量 6 个数：场地长、场地宽、车道宽、黄块边长、两个启停区中心坐标、雷达安装坐标和朝向。

**可走范围**现在按"除了淡黄块，全场地都能走"算（`drivable.white = true`）。
要退回规则原文那种"只能走灰色车道"，把它改成 `false` 即可。

## 五、5×5 网格（按淡黄块边长分格）

你提的"按黄色区域大小分 5×5"，数学上正好成立：

```
2400 = 75 + 5×450 + 75
```

也就是**格子边长 = 淡黄块 450，两边各留 75mm 边距**——图纸上那个「75-85」的标注就是它。

好处是切出来的格子刚好和赛场的物理分区对上：

| 格子 | 实际是什么 |
|---|---|
| **C3** | 十字路口正中心（中心格正好是 225×225 的四分之一车道交汇） |
| B2 / B4 / D2 / D4 | 四个淡黄区（450×450，一格一个，严丝合缝） |
| E5 / E1 | 两个启停区 |
| A/C/E 列 的 1/3/5 行 | 车道延伸段 |
| 边距区域 | 不参与编号（`cell_name()` 返回"边距"） |

编号规则：**列 A→E 从左到右，行 1→5 从下往上**。

界面上的用法：
- 勾「显示 5×5 网格」→ 画布上出虚线格 + 编号；
- 勾「点地图时吸附到格心」→ 点哪都落在格心，不会点到墙上；
- **鼠标移到地图上**：十字虚线 + 提示框，显示 `+297, +302 mm [D4] 距雷达 991mm / 225°`
  —— 世界坐标、所在格子、到雷达的直线距离和方位角，一次全给；
- 「目标格 C3 → 去」→ 直接按编号下目标，不用鼠标；
- 识别结果自动标所在格：`[C4] 圆柱 (123.2, 622.1)`；状态栏汇总 `占用格：C4、C5`。

**尺寸变了会自己适配**：格边长固定取 `cell_grid.cell_mm`（默认跟黄块走 = 450），
边距 = (场地宽 − 5×格边长)/2 自动平分；场地小到塞不下时会自动缩格子。

### 整格封锁（扫到圆柱 → 那格标红、整块不通车）

识别出障碍后，把它所在的那个 450×450 格**整块**标成红色（半透明红 + "不通车"），
规划时这一整格设为禁行（不是只躲 φ50 那 50mm）。

- 勾「整格封锁：占住的格子整块不通车」→ 严格模式（默认）；
- 不勾 → 只按 φ50 实体 + 车半径绕行，格子仍标红但不当硬墙。

因为白区现在也能走，被封锁的格子通常绕得过去（实测：C2/C4/C5 三格全封，
从 E5 去 C1 仍能沿右侧白区绕到，余量 583mm）。
**但如果目标格本身被封锁，就进不去了**——程序会提示
`⚠ C5 本身被封锁，已改到最近的可通行点`，不会假装到了。

注意：**5×5 只是显示/寻址层，A\* 还是在 20mm 细栅格上跑**。格子太粗，直接拿 450
的格做规划会贴着障碍走。要粗规划的话改 `grid.cell_mm` 就行。

## 六、任务路线（全程规划）

路线写在 `field.json` 的 `mission.route`，默认就是比赛流程：

```
START → 扫码区 → 原料区 → 粗加工区 → 暂存区 → 原料区 → 粗加工区 → 暂存区 → START
```

- **START** = 雷达所在的那个启停区（"放在"下拉框选哪个，START 就自动变成哪个），
  同时也当作车的出发点和回归点；
- **扫码区**在两个启停区正中间（y=0，贴右侧内墙，A4 二维码板横放），靠泊点 `(1000,0)`；
- 原料区 / 粗加工区 / 暂存区各自带一个 `approach` **靠泊点**——车停在工位旁边的车道上，
  不压转盘、不压圆环盘；
- **车走格中线**：路径被约束成贴着 5×5 格中线（也就是各区的中心线）的**正交折线**，
  只会在到工位时最后一小段"平移靠泊"离开中线；
- 右侧【规划全程】逐段跑 A\*，**每段独立避障**；哪段没解会红字标出来并给原因；
- 地图上每段一个颜色 + 序号 1..9，一眼看出跑的顺序；
- 右栏给出总长、按 `speed_mm_s` 估的行驶时间；
- 【导出动作序列 JSON】把折线转成 `move`/`turn` 序列，格式对齐 `motion_planner`
  （正 = 左转、逆时针）。**导出的是几何反推，下发前必须核对转向符号。**

实测（模拟雷达 + 3 个障碍占住 C2/C4/C5）：

```
8/8 段可通　总长 15.50 m　按 250 mm/s 约 62 s
1. START→扫码区 1.00m  2. 扫码区→原料区 2.67m  3. 原料区→粗加工区 2.57m
4. 粗加工区→暂存区 1.47m  5. 暂存区→原料区 1.22m  6. 原料区→粗加工区 2.57m
7. 粗加工区→暂存区 1.47m  8. 暂存区→START 2.52m
```

62 s 只是**行驶**时间，不含抓取、放置、等转盘、读码。整轮任务的真实节拍要按抓放动作另算。

### 怎么做到"走中线、靠泊才离开"

不是硬限制，是**代价偏好**：

1. `centerline_cost()` 给"离格中线越远"的格子加代价（bias=3，约等于"偏半格 = 多走半格"）；
   能贴中线就贴，被堵了才自动偏出去。硬限制会在整格封锁时直接无解。
2. 用代价时 A\* 改成 **4 连通**——路径只有直行和原地转，
   正好对上 `motion_planner` 的 `move`/`turn` 指令集，没有圆弧插补。
3. 走完再 `snap_path()` 把 ±10mm 的抖动吸到中线上（只吸 60mm 以内，吸完还要复查合法性），
   不然线路会在 890/910 之间来回抖。
4. `split_backbone()` 把每段切成"主干"和"靠泊"两部分，右栏分别报米数。

代价：总长从自由规划的 15.50 m 涨到 **18.38 m**（+18%）。这是走中线的必要开销——
换来的是路径规则、可重复、跟 `move/turn` 指令一一对应。

### 工位格不封锁

原料区的转盘就长在 C5 格里。如果按"整格封锁"把 C5 封了，**原料区就永远到不了**。
所以：**格子里有工位（含扫码区）时不封锁**，工位上的物体靠实体半径绕开就够了。
识别结果里会注明 `C5 是工位格，不封锁`。

## 七、雷达协议（以官方文档为准）

全部按《COIN-D6 激光雷达数据格式标准说明 V1.0》第 4~5 页：

```
帧长 = 10 + 3×LSN
偏移 0   2   AA 55 帧头
     2   1   M&T   bit0=T(0=点云包 1=起始包)，bit7:1=扫描频率
     3   1   LSN   本包点数（起始包为 1）
     4   2   FSA   起始角（小端，bit0 是固定为 1 的校验位）
     6   2   LSA   结束角（同上）
     8   2   CS    校验码（双字节异或，在头里，不在帧尾）
     10  3N  点数据：Si_L, Si_2nd, Si_H
```

```python
距离(mm) = Si_H*64 + (Si_2nd >> 2)            # 14bit
强度     = (Si_2nd & 0x03)*64 + (Si_L >> 2)   # 8bit
角度(°)  = FSA/128，中间点按 (LSA-FSA)/(LSN-1) 线性插值
```

命令：启动 `AA 55 F0 0F`，停止 `AA 55 F5 0A`。雷达**顺时针**旋转，10Hz。

### 我之前在这里错了两次，记下来免得再犯

1. **点数据起点是 10，不是 8。** CS 在头里不在帧尾。帧长 `8+3N+2` 和 `10+3N`
   数值恰好相同，所以帧同步一直"看起来正常"，但每点错位 2 字节。
2. **距离是「高字节×64 + 中字节>>2」**，我写成了「低字节 | 中字节<<8」。
   这两个字节约等于 4 倍关系 —— 所以点云形状是对的、**尺寸全错 4 倍**
   （实测 15cm 显示成 60cm，抓包复核倍数 4.12）。

> 连带纠正：塔克 STM32 例程 `ax_laser.c:292/306` 的
> `((u16)buf[12+i*3]<<6) + (buf[11+i*3]>>2)` **是标准公式，完全正确**。
> 我之前说它错，是我错了，特此更正。

## 九、已知限制（都是物理限制，不是 bug）

**1. φ50 圆柱只有 1.2~1.5m 内能测准**
D6 角分辨率 0.9°：1m 处每点间隔 15.7mm，φ50 能分到约 3 个点；2m 处 31mm，只剩 1~2 个点。
所以代码里：
- 距离近、点够多 → 标 `φ50` 精确圈；
- 点太少 → 标 `φ50?`，位置可信、半径存疑；
- 只有 1~2 个点 → 标"未知"（橙色），但规划时照样当障碍物。

**2. 圆柱堵在 400 宽车道中间时，物理上过不去**
车 300 + 圆柱 50 = 350 < 400，理论能过，但只剩 25mm/边的余量。
所以 `plan_path()` 会按 100%→50% 逐档缩小膨胀半径重试，并在状态栏如实报告
"最小余量 xx mm" 和"放宽到 xx% 才通得过"。余量 <20mm 会提示"很勉强"。

**3. 走中线必然比自由规划绕**
曼哈顿路径天生比直线远。18.38 m vs 15.50 m 就是这笔账。
如果某段特别急（比如时间卡死），把「沿格中线」取消勾选，立刻回到直连最短路径。

**4. "整格封锁"是保守策略，会浪费可通行面积**
一个 φ50 圆柱只占 450×450 里的 1.5%，封锁整格等于把 98% 的可走面积也判死。
好处是决策简单、不会算出一条"贴着圆柱擦过去"的险路；代价是本来就窄的通道更容易被整段放弃。
现场建议：赛道宽裕时用严格模式，卡边时关掉它、靠"实体绕行 + 余量提示"。

**5. 雷达看不见白区边界**
它只能看到"有高度"的东西。所以路径能走哪儿、哪儿是黄块，全靠**参数模型**，不是雷达。模型填错 = 规划错。

## 十、待现场确认

0. **白区能不能走，得你自己确认**：规则原文写的是"全部离开启停区后只能在灰色车道上行驶，
   进入其它颜色区域（除启停区）结束比赛"。现在按你的要求放开了白区，等于放宽了约束。
